# OmaShaders: how it works and how to add effects

Full-screen GLSL effects over all monitors via Hyprland `decoration:screen_shader`.
They run inside the compositor on the GPU: no extra window, no CPU use, same cost on every monitor.

    bin/omashaders list | status | set NAME | off | toggle [NAME] | next | prev   (add -a to include animated) | animated [on|off|toggle] | gpu
    bin/omashaders effect [status|list|set NAME|off] | color [status|list|set NAME|off]
    bin/omashaders strength [effect|color|wall|mouse [N|+N|-N|reset]] | power [status|on|off|toggle] [--notify]

Effects live in `shaders/*.frag`, colour grades in `colors/*.frag` (GLSL ES 3.00, uniforms `tex`, `time`, input `v_texcoord`).
Validate with `glslangValidator -S frag shaders/NAME.frag`. Hyprland runs only one screen shader, so with an effect and a colour set,
`bin/compose-shader` merges them into `<state dir>/built/EFFECT@S+COLOR@S.frag` (effect first, the colour then reads the effect's result, each with its strength baked in as a constant because Hyprland has no custom uniforms);
`off` clears both, `effect off` / `color off` one layer. `set NAME` with a colour name sets the colour layer.
Hyprland 0.56 uses the Lua parser: the shader is set at runtime with `hyprctl eval`, `hyprctl keyword` does not work.

## Cost of animated shaders
Any shader that declares `uniform float time;` makes Hyprland show a red warning and need
`debug:damage_tracking = off`, which redraws the whole screen every frame (big GPU cost).
Static shaders must NOT declare `time`. Animated ones (Motion, plus hologram, matrix, fireflies, underwater, snowfall in Ambient)
are costly: `omashaders` sets `debug:damage_tracking=0` itself when an animated shader is applied
(no Hyprland warning) and back to 2 for static ones and for off. A warning left over from before is cleared with `hyprctl reload`.

## Adding a shader
Effect: drop `shaders/NAME.frag` with two comment lines right after `#version 300 es`: `// category: Lens|Retro|Devices|Art|Mood|Ambient|Motion` and `// desc: one line shown in the menu`.
Colour: `colors/NAME.frag`, category `Comfort|Color|Retro|Devices`; it must be a per-pixel function of `texture(tex, v_texcoord)` only (one such call, no other `v_texcoord`, no `gl_FragCoord`, no `time`), because the composer swaps that call for the effect's output and prefixes the colour's helper functions with `c_`.
Wallpaper and cursor strength (`strength-wall`, `strength-mouse` in the state dir) is the opacity of the overlay window over the real wallpaper / screen (`WallpaperFx.qml`, `MouseFx.qml`); for the cursor-bend effects `bin/cursor-bend` blends plain and bent screen with it inside the composed shader.

Custom colours: the name `custom-RRGGBB` (any hex) is turned by `bin/compose-shader --custom STATE_DIR NAME` into a generated grade in `<state dir>/custom-colors/`, so favourites, combos and strength treat it like any shipped colour.

Strength: add `// strength: N` for the start value (default 100). By default the result is blended with the untouched screen (`mix(input, result, S)`), which is right for tints and overlays. Shaders whose look changes shape (pixel blocks, blur radius, curvature) add `// strength-mode: native` and read `STRENGTH` (0.0-1.0) themselves, so 0 % really is the original screen and the start value is readable.
Check everything with `bin/shader-check` (composes every effect and colour at 50 % and validates it with glslangValidator; standalone validation of a native shader fails on `STRENGTH`). Preview without touching the desktop: `bin/shader-preview IN.png SHADER.frag OUT.png [TIME]` (CPU rendering with Mesa; build the shader first with `bin/compose-shader`).

## Mixing two effects

`bin/compose-shader --fx2 FILE PCT stack|blend MIX` (and `--col2`) add a second layer. State: `effect2`, `color2`, `mix-effect`, `mix-color` (`MODE VALUE`); `bin/omashaders mix` edits them, `apply` passes them on and names the built file `fx@s+...` with a signature so mixes cache separately. The first layer cannot just be run twice, because an effect may sample `tex` at any UV, so layer A is rewritten into `vec4 fx_eval(vec2 uv)` (`v_texcoord` becomes the global `fx_uv`, `fragColor` the global `fx_o`) and in stack mode B's `texture(tex, ...)` calls become `fx_eval(...)`. Blend is `mix(fx_eval(v_texcoord), fy_eval(v_texcoord), share)`. `gl_FragCoord` is not remapped (the error is invisible). Colours are per-pixel on `fx_in`, so they simply run one after the other (stack) or are mixed (blend). Stack amount is the second's own strength; blend amount is the share of B and B then uses its remembered or start strength. `bin/cursor-bend` reads the same files, so bend shaders keep a mix. Window shaders do not: `compose` accepts the second layers but `window_file` does not pass them. `bin/shader-check` composes every effect and colour as the second layer in both modes.

## Window frames

`frames/*.frame` are presets of Hyprland's own shadow and border options (not GLSL; HyprWindowShade only paints inside the window). Format: `# category:`, `# desc:`, then `key=value` lines (colours `RRGGBBAA`; keys cover rounding, border size, active / inactive border, shadow range, power, colour, inactive colour, offset, scale, sharp, and `spin=SPEED`). `bin/frame-apply` (python3) reads `<state dir>/window-frame`, saves the current look once as `frame-base.json` (keyed by `HYPRLAND_INSTANCE_SIGNATURE`) and sends one `hyprctl eval 'hl.config({...})'`; an empty name restores that baseline. `spin` sets `hl.animation({leaf="borderangle", style="loop", bezier="linear"})`, which only starts after a focus event, so it re-focuses the active window (`hl.dsp.focus({window="address:..."})`). Gotchas: an unset `decoration:shadow:color_inactive` reads back as `ffffffff` and setting that explicitly gives white inactive shadows, so the active shadow colour is used instead; `hyprctl reload` drops runtime overrides, so the widget runs `window frame reload` (forget baseline, re-apply) on `configreloaded`. `listall` emits frames with section `frame`; the widget shows them as `f:` categories in the Windows column.

## Window shaders

`bin/compose-shader --window` builds the same merged shader for windows: `#version 320 es` and the result is multiplied by the window's own alpha (`vec4(rgb * a, a)`, the plugin expects premultiplied output), so rounded corners and transparent terminals stay intact. `bin/omashaders window ...` keeps the state (`window-effect`, `window-color`, `window-target`, `window-strength-*`, `window-applied`, `window-sig`) and calls `hl.plugin.HyprWindowShade.classshader(CLASS, FILE)` through `hyprctl eval` for every targeted app class, and `"clear"` for the ones it set before. Targets named `layer:NAMESPACE` (from `hyprctl layers -j`, listed by `window classes` after the app classes) go to `hl.plugin.HyprWindowShade.layershader(NAMESPACE, FILE)` instead, because bars, panels and overlays are layer surfaces; `*` includes them through `all_layers` (open layers + `ALL_LAYERS_KNOWN` pre-registered so a flyout is shaded from its first frame + layers shaded before; excluded: bar, background, wallpaper-fx, mouse overlay, lock preview, `*-dismiss`, `*-ghost`); the plugin's layer catch-all `*` is not used because it stacks with specific entries and cannot be overridden per layer. The widget also syncs on `openlayer`. The background/wallpaper/mouse overlay namespaces are not offered in the list. The OmaShaders menu is the shared `omarchy-keyboard-panel`, so it is shaded too. The window shader keeps the layer's alpha, so transparent margins stay transparent. Per-app settings: `window-app/CLASS/{effect,color,strength-effect,strength-color}` (the `WSCOPE` variable picks the directory, `window -a CLASS ...` sets it; `app_seed` copies the all-windows files on the first change). `window_apply` maps every target class to the all-windows file, then replaces the entry of each class that has an override (an override with no effect and colour removes it); `window-apps` is a TSV summary (`CLASS effect color effect% color%`) rewritten after each `window` command for the menu to watch. Built files live in `<state dir>/built-win/` and are deleted after 60 minutes only when no class uses them. Notes from testing on Hyprland 0.56: use `classshader` only (a window rule or tag created at runtime leaves a `shader:` tag that cannot be removed); a class is an exact match; a missing file is skipped silently and an already compiled shader stays cached until `reloadshaders()`; apply with `hyprctl eval`, `hyprctl dispatch` prints "expected a dispatcher" although it works. The widget calls `window sync` when a window opens while the target is *All windows*, and `window apply` at start. `bin/shader-check` also validates every effect and colour in window mode.

## Reacting to what moves on screen
Not possible inside a Hyprland screen shader: it gets only the current frame (no previous frame, no custom inputs), so it cannot compare frames. Possible variants: a cursor-reactive shader (a helper rewrites a constant and re-applies; recompiles each time, so only a few updates per second) or a Quickshell overlay with a screencopy feedback loop (heavy). Built since as the Bend cursor effects (below), though not as a frame-comparing shader.

## Wallpaper and cursor effects
`wallpaper-effects/NAME.frag` and `mouse-effects/NAME.frag` are Qt shaders; the compiled `.frag.qsb` next to each is committed so users need no build tools.
They are drawn by `WallpaperFx.qml` and `MouseFx.qml` in layer-shell windows (one per monitor) hosted by the first monitor's bar.
A new wallpaper effect file that the menu's built-in list does not know appears under "More" the next time the menu opens (no shell restart); give it `// label:` and `// hint:` header lines. Only QML changes need a shell restart.

Mouse reaction: every wallpaper shader that follows the pointer has its body in `fxMain(vec2 mpx)` and a shared `main()` wrapper that renders `fxMain(mouse)` at `react` = 1 (one pass), `fxMain(away)` at 0 (pointer far away, parallax uses the screen centre), and a mix of both in between (two passes; above 1 it extrapolates to exaggerate). The UBO ends `... cCream, cTarget, react, range` (Smoke has `tr0..tr3` after that), in the same order in `bin/wallpaper-preview`. `colorreact.frag` (Colour reactor) matches pixels to `cTarget` by OKLab distance (tolerance from `range`) and only those pixels are pulled toward the pointer, rippled and lit. State: `react-wall` (0-200), `wall-range` (0-100), `wall-target` (RRGGBB); `omashaders wallopt react|range|target`.
Recompile after editing with `bin/build-wallpaper-effects` / `bin/build-mouse-effects` (needs qt6-shadertools).
`bin/wallpaper-step next|prev|status|pick` steps or picks the wallpaper image; `bin/gpu-usage` prints `OVERALL SHELL HYPRLAND USED_MB TOTAL_MB`.
`bin/cursor-watch` prints the pointer position from the Hyprland socket (about 40 times a second) and exits when its parent exits.

## Bend cursor effects

`cursor-shaders/NAME.frag` defines `vec4 bend(vec2 uv)` and may use `CUR` (pointer, pixels, monitor-local), `CVEL` (pixels per second), `CT` (seconds since the pointer last moved), `RES` and `texture(tex, ...)`. Header lines: `// category: Bend`, `// desc: ...`, and `// tail: N` if the effect keeps changing for N seconds after the pointer stops. `bin/compose-shader --cur FILE` merges it with the Screen and Color layers (the Screen layer's `texture(tex, ...)` calls are redirected through the bend). `bin/cursor-bend` rewrites the `CUR`/`CVEL`/`CT`/`CMARK` constants and applies the file, at most 30 times a second; the multi-monitor marker is described in the README. Besides the pointer, a bend shader gets the trail: `CTR[8]` holds the 8 previous pointer positions (newest first, about 35 ms apart, monitor-local pixels). `cur_pt(i)` returns the trail point i (0 = pointer, up to 8) and `cur_seg(p, i, dir, len, h)` returns the distance from pixel `p` to trail segment i, with its direction, length and position h along it (see `// category: Follow` shaders such as `smudge.frag`). Use `// tail: 0.5` or more so the trail has time to collapse before updates stop. `bin/shader-check` validates every bend shader.

## Cost log and report

`bin/perf-log` (python3, started by the widget at load, one copy via `perf.lock`, re-execs itself when the file changes, stops with `perf-off`) appends JSON lines to `<state dir>/perf.jsonl`: `ev` start / change / sample / stop, `layers` (`screen:NAME`, `screen2:`, `color:`, `wall:`, `cursor:`, `win:`, `wincolor:`, `frame:`), strengths, `anim`, `gpu` (whole GPU %), `hypr` / `shell` (their SM % from `nvidia-smi pmon -c 2 -s u`), `hcpu` / `scpu` (CPU % from /proc), vram, watt, temp. Samples within 3 s of a change are marked `settle` and ignored. Cost of a layer = median of (hypr + shell) while it was on minus the median while nothing was on; layers only ever seen in combinations are averaged over those. `report` also writes `perf-report.md` and `perf-summary.tsv` (`kind name rating cost samples`, read by `omashaders listall` to append `[measured: ...]` to descriptions and by the widget for the active line). `bench` holds `bench.lock` so the sampler stays quiet, switches effects through `omashaders`, and restores the saved state files in a `finally`. Crash correlation uses `coredumpctl list --json` and the last log record before each crash; a start record without a preceding stop means the shell died uncleanly.
