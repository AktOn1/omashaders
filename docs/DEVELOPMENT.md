# OmaShaders: how it works and how to add effects

Full-screen GLSL effects over all monitors via Hyprland `decoration:screen_shader`.
They run inside the compositor on the GPU: no extra window, no CPU use, same cost on every monitor.

    bin/omashaders list | status | set NAME | off | toggle [NAME] | next | prev   (add -a to include animated) | animated [on|off|toggle] | gpu
    bin/omashaders effect [status|list|set NAME|off] | color [status|list|set NAME|off]
    bin/omashaders strength [effect|color|wall|mouse [N|+N|-N|reset]] | power [status|on|off|toggle] [--notify]

Effects live in `shaders/*.frag`, colour grades in `colors/*.frag` (GLSL ES 3.00, uniforms `tex`, `time`, input `v_texcoord`).
Validate with `glslangValidator -S frag shaders/NAME.frag`. Hyprland runs only one screen shader, so with an effect and a colour set,
`bin/compose-shader` merges them into `<state dir>/built/EFFECT@S+COLOR@S.frag` (effect first, the colour then reads the effect's result, each with its strength baked in as a constant because Hyprland has no custom uniforms);
`off` clears both, `effect off` / `color off` one layer. `set NAME` with a colour name sets the colour layer.
Hyprland 0.56 uses the Lua parser: the shader is set at runtime with `hyprctl eval`, `hyprctl keyword` does not work.

## Cost of animated shaders
Any shader that declares `uniform float time;` makes Hyprland show a red warning and need
`debug:damage_tracking = off`, which redraws the whole screen every frame (big GPU cost).
Static shaders must NOT declare `time`. Animated ones (Motion, plus hologram, matrix, fireflies, underwater, snowfall in Ambient)
are costly: `omashaders` sets `debug:damage_tracking=0` itself when an animated shader is applied
(no Hyprland warning) and back to 2 for static ones and for off. A warning left over from before is cleared with `hyprctl reload`.

## Adding a shader
Effect: drop `shaders/NAME.frag` with two comment lines right after `#version 300 es`: `// category: Lens|Retro|Devices|Art|Mood|Ambient|Motion` and `// desc: one line shown in the menu`.
Colour: `colors/NAME.frag`, category `Comfort|Color|Retro|Devices`; it must be a per-pixel function of `texture(tex, v_texcoord)` only (one such call, no other `v_texcoord`, no `gl_FragCoord`, no `time`), because the composer swaps that call for the effect's output and prefixes the colour's helper functions with `c_`.
Wallpaper and cursor strength (`strength-wall`, `strength-mouse` in the state dir) is the opacity of the overlay window over the real wallpaper / screen (`WallpaperFx.qml`, `MouseFx.qml`); for the cursor-bend effects `bin/cursor-bend` blends plain and bent screen with it inside the composed shader.

Combos are lines `screen|wall|mouse|color|name` in `<state dir>/combos` (the name is optional; `comboBase()` is the first four fields and is what saving, de-duplication and the current-combo mark compare). `renameCombo()` rewrites the line, `n` on the Combos menu and the IPC `comboRename N NAME` call it; the `starter-combos` file uses the same format.

Custom colours: the name `custom-RRGGBB` (any hex) is turned by `bin/compose-shader --custom STATE_DIR NAME` into a generated grade in `<state dir>/custom-colors/`, so favourites, combos and strength treat it like any shipped colour.

Strength: add `// strength: N` for the start value (default 100). By default the result is blended with the untouched screen (`mix(input, result, S)`), which is right for tints and overlays. Shaders whose look changes shape (pixel blocks, blur radius, curvature) add `// strength-mode: native` and read `STRENGTH` (0.0-1.0) themselves, so 0 % really is the original screen and the start value is readable.
Check everything with `bin/shader-check` (composes every effect and colour at 50 % and validates it with glslangValidator; standalone validation of a native shader fails on `STRENGTH`). Preview without touching the desktop: `bin/shader-preview IN.png SHADER.frag OUT.png [TIME]` (CPU rendering with Mesa; build the shader first with `bin/compose-shader`).

## Mixing two effects

`bin/compose-shader --fx2 FILE PCT stack|blend MIX` (and `--col2`) add a second layer. State: `effect2`, `color2`, `mix-effect`, `mix-color` (`MODE VALUE`); `bin/omashaders mix` edits them, `apply` passes them on and names the built file `fx@s+...` with a signature so mixes cache separately. The first layer cannot just be run twice, because an effect may sample `tex` at any UV, so layer A is rewritten into `vec4 fx_eval(vec2 uv)` (`v_texcoord` becomes the global `fx_uv`, `fragColor` the global `fx_o`) and in stack mode B's `texture(tex, ...)` calls become `fx_eval(...)`. Blend is `mix(fx_eval(v_texcoord), fy_eval(v_texcoord), share)`. `gl_FragCoord` is not remapped (the error is invisible). Colours are per-pixel on `fx_in`, so they simply run one after the other (stack) or are mixed (blend). Stack amount is the second's own strength; blend amount is the share of B and B then uses its remembered or start strength. `bin/cursor-bend` reads the same files, so bend shaders keep a mix. Window shaders mix too (1.17): `MIXWIN=1` makes `mixstate` read `effect2` / `color2` / `mix-*` from the scope (`window-effect2`, `window-mix-effect`, ... or `window-app/CLASS/...`, which `app_seed` copies), `window mix effect|color ...` runs the same `mix_run`, `window_file` passes `--fx2/--col2` and names the file with the mix signature, and `mix_summary` writes `window-mix` (TSV `SCOPE effect2 color2 emode eamt cmode camt`, `*` = All windows) for the menu. Setting a new window effect or colour clears its second. Wallpaper effects mix inside the shell: `wp-effect2` and `wp-mix` (`MODE VALUE`) are written by `Core.qml`; `WallpaperFx.qml` draws the second `FxLayer` over the first (stack: it samples a `ShaderEffectSource` of the first layer; blend: both sample the image) at opacity = amount, inside a `layer.enabled` item whose opacity is the wallpaper strength. `bin/shader-check` composes every effect and colour as the second layer in both modes.

## Window frames

`frames/*.frame` are presets of Hyprland's own shadow and border options (not GLSL; HyprWindowShade only paints inside the window). Format: `# category:`, `# desc:`, then `key=value` lines (colours `RRGGBBAA`; keys cover rounding, border size, active / inactive border, shadow range, power, colour, inactive colour, offset, scale, sharp, and `spin=SPEED`). `bin/frame-apply` (python3) reads `<state dir>/window-frame`, saves the current look once as `frame-base.json` (keyed by `HYPRLAND_INSTANCE_SIGNATURE`) and sends one `hyprctl eval 'hl.config({...})'`; an empty name restores that baseline. `spin` sets `hl.animation({leaf="borderangle", style="loop", bezier="linear"})`, which only starts after a focus event, so it re-focuses the active window (`hl.dsp.focus({window="address:..."})`). Gotchas: an unset `decoration:shadow:color_inactive` reads back as `ffffffff` and setting that explicitly gives white inactive shadows, so the active shadow colour is used instead; `hyprctl reload` drops runtime overrides, so the widget runs `window frame reload` (forget baseline, re-apply) on `configreloaded`. `listall` emits frames with section `frame`; the widget shows them as `f:` categories in the Windows column.

## Window shaders

`bin/compose-shader --window` builds the same merged shader for windows: `#version 320 es` and the result is multiplied by the window's own alpha (`vec4(rgb * a, a)`, the plugin expects premultiplied output), so rounded corners and transparent terminals stay intact. `bin/omashaders window ...` keeps the state (`window-effect`, `window-color`, `window-target`, `window-strength-*`, `window-applied`, `window-sig`) and calls `hl.plugin.HyprWindowShade.classshader(CLASS, FILE)` through `hyprctl eval` for every targeted app class, and `"clear"` for the ones it set before. Targets named `layer:NAMESPACE` (from `hyprctl layers -j`, listed by `window classes` after the app classes) go to `hl.plugin.HyprWindowShade.layershader(NAMESPACE, FILE)` instead, because bars, panels and overlays are layer surfaces; `*` includes them through `all_layers` (open layers + `ALL_LAYERS_KNOWN` pre-registered so a flyout is shaded from its first frame + layers shaded before; excluded: bar, background, wallpaper-fx, mouse overlay, lock preview, `*-dismiss`, `*-ghost`); the plugin's layer catch-all `*` is not used because it stacks with specific entries and cannot be overridden per layer. The widget also syncs on `openlayer`. The background/wallpaper/mouse overlay namespaces are not offered in the list. The OmaShaders menu is the shared `omarchy-keyboard-panel`, so it is shaded too; `window classes` prints the open classes then `all_layers` (so the menu is in the app picker even though its layer does not exist yet when the list is fetched), and `omashaders-bend-marker` is excluded like the other overlays. The window shader keeps the layer's alpha, so transparent margins stay transparent. Per-app settings: `window-app/CLASS/{effect,color,strength-effect,strength-color}` (the `WSCOPE` variable picks the directory, `window -a CLASS ...` sets it; `app_seed` copies the all-windows files on the first change). `window_apply` maps every target class to the all-windows file, then replaces the entry of each class that has an override (an override with no effect and colour removes it); `window-apps` is a TSV summary (`CLASS effect color effect% color%`) rewritten after each `window` command for the menu to watch. Built files live in `<state dir>/built-win/` and are deleted after 60 minutes only when no class uses them. Notes from testing on Hyprland 0.56: use `classshader` only (a window rule or tag created at runtime leaves a `shader:` tag that cannot be removed); a class is an exact match; a missing file is skipped silently and an already compiled shader stays cached until `reloadshaders()`; apply with `hyprctl eval`, `hyprctl dispatch` prints "expected a dispatcher" although it works. The widget calls `window sync` when a window opens while the target is *All windows*, and `window apply` at start. `bin/shader-check` also validates every effect and colour in window mode.

## Reacting to what moves on screen
Not possible inside a Hyprland screen shader: it gets only the current frame (no previous frame, no custom inputs), so it cannot compare frames. Possible variants: a cursor-reactive shader (a helper rewrites a constant and re-applies; recompiles each time, so only a few updates per second) or a Quickshell overlay with a screencopy feedback loop (heavy). Built since as the Bend cursor effects (below), though not as a frame-comparing shader.

## Wallpaper and cursor effects
`wallpaper-effects/NAME.frag` and `mouse-effects/NAME.frag` are Qt shaders; the compiled `.frag.qsb` next to each is committed so users need no build tools.
They are drawn by `WallpaperFx.qml` and `MouseFx.qml` in layer-shell windows (one per monitor) hosted by the first monitor's bar.
A new wallpaper effect file that the menu's built-in list does not know appears the next time the menu opens (no shell restart). Header lines: `// label:` (menu name), `// hint:` (grey text) and `// category:` (the group it is listed in: the name of an existing group such as `Weather and nature` adds it there, any other name creates a new group, no line puts it under "More"). `bin/omashaders listall` carries the category as the 7th column. The other menus (screen, colour, cursor, frames) already build their categories from the `// category:` header, so nothing needs QML edits.

Mouse reaction: every wallpaper shader that follows the pointer has its body in `fxMain(vec2 mpx)` and a shared `main()` wrapper that renders `fxMain(mouse)` at `react` = 1 (one pass), `fxMain(away)` at 0 (pointer far away, parallax uses the screen centre), and a mix of both in between (two passes; above 1 it extrapolates to exaggerate). The UBO ends `... cCream, cTarget, react, range` (Smoke has `tr0..tr3` after that), in the same order in `bin/wallpaper-preview`. `colorreact.frag` (Colour reactor) matches pixels to `cTarget` by OKLab distance (tolerance from `range`) and only those pixels are pulled toward the pointer, rippled and lit. State: `react-wall` (0-200), `wall-range` (0-100), `wall-target` (RRGGBB); `omashaders wallopt react|range|target`.
Speed and zoom (v1.18.0): speed is applied in `WallpaperFx.qml` (the `time` uniform is an effect clock that advances `speed` times real time; the trail sampler of `smoke` uses real time). Zoom is the shared vertex shader `wallpaper-effects/zoom.vert` (rebuilt by `bin/build-wallpaper-effects`), which scales `qt_TexCoord0` about the centre by `zoom`, and each fragment shader's `wall()` undoes that scaling when sampling the picture (`(uv-0.5)*zoom+0.5`), so only the effect scales and the wallpaper stays put (v1.18.1); new shaders must define `wall()` the same way; the pointer and trail uniforms are transformed the same way in QML. Every fragment shader declares `float zoom;` right after `float range;` (in the std140 padding, so later members like `tr0` keep their offsets) because Qt wants the vertex and fragment blocks to agree. New shaders must keep that line. State files `wall-speed` (0-300) and `wall-zoom` (25-300), CLI `omashaders wallopt speed|zoom`. `bin/wallpaper-preview` takes env `ZOOM` and `SPEED`.
Recompile after editing with `bin/build-wallpaper-effects` / `bin/build-mouse-effects` (needs qt6-shadertools).
`bin/wallpaper-step next|prev|status|pick` steps or picks the wallpaper image; `bin/gpu-usage` prints `OVERALL SHELL HYPRLAND USED_MB TOTAL_MB`.
`bin/cursor-watch` prints the pointer position from the Hyprland socket (about 40 times a second) and exits when its parent exits.

## Bend cursor effects

`cursor-shaders/NAME.frag` defines `vec4 bend(vec2 uv)` and may use `CUR` (pointer, pixels, monitor-local), `CVEL` (pixels per second), `CT` (seconds since the pointer last moved), `RES` and `texture(tex, ...)`. Header lines: `// category: Bend`, `// desc: ...`, and `// tail: N` if the effect keeps changing for N seconds after the pointer stops. `bin/compose-shader --cur FILE` merges it with the Screen and Color layers (the Screen layer's `texture(tex, ...)` calls are redirected through the bend). `bin/cursor-bend` rewrites the `CUR`/`CVEL`/`CT`/`CMARK` constants and applies the file, at most 30 times a second; the multi-monitor marker is described in the README. Besides the pointer, a bend shader gets the trail: `CTR[8]` holds the 8 previous pointer positions (newest first, about 35 ms apart, monitor-local pixels). `cur_pt(i)` returns the trail point i (0 = pointer, up to 8) and `cur_seg(p, i, dir, len, h)` returns the distance from pixel `p` to trail segment i, with its direction, length and position h along it (see `// category: Follow` shaders such as `smudge.frag`). Use `// tail: 0.5` or more so the trail has time to collapse before updates stop. `bin/shader-check` validates every bend shader.

## Cost log and report

`bin/perf-log` (python3, started by the widget at load, one copy via `perf.lock`, re-execs itself when the file changes, stops with `perf-off`) appends JSON lines to `<state dir>/perf.jsonl`: `ev` start / change / sample / stop, `layers` (`screen:NAME`, `screen2:`, `color:`, `wall:`, `cursor:`, `win:`, `wincolor:`, `frame:`), strengths, `anim`, `gpu` (whole GPU %), `hypr` / `shell` (their SM % from `nvidia-smi pmon -c 2 -s u`), `hcpu` / `scpu` (CPU % from /proc), vram, watt, temp. Samples within 3 s of a change are marked `settle` and ignored. Cost of a layer = median of (hypr + shell) while it was on minus the median while nothing was on; layers only ever seen in combinations are averaged over those. `report` also writes `perf-report.md` and `perf-summary.tsv` (`kind name rating cost samples`, read by `omashaders listall` to append `[measured: ...]` to descriptions and by the widget for the active line). `bench` holds `bench.lock` so the sampler stays quiet, switches effects through `omashaders`, and restores the saved state files in a `finally`. Crash correlation uses `coredumpctl list --json` and the last log record before each crash; a start record without a preceding stop means the shell died uncleanly.


## Combos, fullscreen pause, cursor size and speed, audio effects (v1.22.0)

- **Combo lines** (`combos` / `starter-combos`): `screen|wall|mouse|color` or `...|name` or `...|name|winEffect|winColor|winFrame`. A line without the window fields leaves the Windows settings as they are when applied; a line with them sets Windows effect, colour and frame for all windows (`omashaders window ...`, run one after the other in one shell so the plugin sees a consistent state). `comboBase()` is the identity of a combo (name removed); a saved 4-part line still matches while the live Windows settings differ.
- **Pause while fullscreen:** state file `pause-fullscreen` (setting, `omashaders fullscreen on|off|toggle|status`) and `fs-paused` (set by `omashaders fullscreen pause`, cleared by `resume`; `is_disabled` in `bin/omashaders` is true for the manual `disabled` file or `fs-paused`, so screen shader, window shaders and frames follow with no other change). `bin/fullscreen-watch` (python) follows Hyprland's event socket (`.socket2.sock`) and prints 1 / 0 for "the focused monitor's workspace has a fullscreen window" (`j/monitors` + `j/workspaces` `hasfullscreen`), once at start and on every fullscreen / workspace / focus / window event; Core turns that into `fsActive`, `effectsOff = paused || fsPaused` stops the wallpaper, cursor overlay, bend and the pointer poller, and `fullscreen pause|resume` handles the Hyprland side. Core runs `fullscreen resume` at load so a leftover flag never sticks.
- **Cursor Size and Speed:** state files `mouse-size` (25-300) and `mouse-speed` (0-300), CLI `omashaders mouseopt size|speed`, sliders under the Cursor strength slider, keys `z`/`Z` and `v`/`V`. `MouseFx.qml` scales the overlay item about the pointer (`Scale` transform, so cursor shaders must compute in pixel units from `qt_TexCoord0 * res`, `mouse` and `h0..h3`, never `gl_FragCoord`) and advances `time` at `speed` times real time. Bend effects ignore both (they are screen shaders rewritten by `bin/cursor-bend`).
- **Audio-reactive effects:** a wallpaper or cursor effect whose id starts with `audio-` makes the shell run `bin/audio-level` (python3 + numpy + `parec` from the default sink's monitor, 16 kHz mono, 40 ms windows; prints `level bass mid treble`, each 0-1, auto-scaled with a slow peak follower, fast attack and slower release; `--stdin` reads raw s16le for tests). It stops when no such effect is on. `WallpaperFx.qml` and `MouseFx.qml` expose `audio`, `bass`, `mid`, `treble`; a shader reads them by declaring `float audio; float bass; float mid; float treble;` at the END of its uniform block (Qt maps ShaderEffect properties to uniform members by name; shaders without the members ignore them). In silence all four are 0, so audio effects need a calm idle look. `bin/wallpaper-preview` packs the UBO in a fixed order, so a test copy has to append the four floats.
- Hyprland screen shaders cannot receive audio (and `cursor-bend` rewrites the shader file, which is too heavy at audio rates), so in an audio-reactive combo only the Wallpaper and Cursor pieces move with the sound.

## Hot reload (v1.21.0)

Nothing in this plugin needs `omarchy-restart-shell` while you work on it, except changes to `BarWidget.qml` itself (and `manifest.json`).

- New or edited files in `shaders/`, `colors/`, `wallpaper-effects/`, `cursor-shaders/`, `mouse-effects/`, `frames/` and `bin/` are read again the next time the menu opens (new wallpaper categories come from `// category:`).
- QML: Omarchy loads `BarWidget.qml` once at shell start, so it is only a thin host. The real code is `Core.qml` (what `BarWidget.qml` was before 1.21). The host watches `Core.qml`, `WallpaperFx.qml`, `MouseFx.qml` and `BendMarker.qml` (FileView) and, 0.4 s after a change, compiles all four with a new `?v=` query string (Qt caches components by URL, so the query defeats the cache), then destroys the running Core and creates the new one 0.15 s later (`createObject(root, {host: root, ver: ver})`; the gap lets the old IPC handler and helper processes go first). Core's `bar`, `settings`, `moduleName` and `setting()` come from the host, the host forwards `opened`, `open()`, `close()`, `toggle()` and `closeForPopoutSwitch()` that the bar calls. If any of the four files has an error the swap is refused: the old Core keeps running, the host logs `OmaShaders: not reloading ...`, sends a desktop notification and shows a red `!` on the bar icon until the next good save. Sibling QML files are loaded from Core through `FxHost` loaders with `root.sub("File.qml")` (versioned url); a new sibling QML file must be loaded the same way and added to `files` in `BarWidget.qml`, never as a plain type name inside Core.qml. A reload closes an open menu and restarts the helper processes and wallpaper/cursor windows (a short flicker); all state is in files, so nothing is lost.
- `omarchy-shell io.github.akton1.omashaders-host reload` forces a reload, `... status` prints `reloads=N running=yes|no error=none|first error line` (use it in scripts and tests).
- Omarchy has its own hot reload (any save under `~/.config/omarchy/plugins/`, found by `inotifywait -r`), but it does not follow symlinks, so a plugin installed with `ln -s` from a source tree never triggers it; that is why the host has its own watcher. With a real directory (store install, `cp`) Omarchy's reload fires instead: it rebuilds every plugin widget, so the host and its Core are recreated from scratch. A broken edit then removes the icon (only the red `!` stays) until fixed. For development use the symlink layout.
- A watcher `FileView` on four files costs nothing for people who never edit the plugin.
- `vm-check.sh` (run by `vm-test omashaders`) proves all of this in the Omarchy VM in both layouts: edit the bar glyph, broken edit refused, restore, broken sibling, new wallpaper categories in the open menu, an edited menu string, forced reloads (no memory growth, one perf-log, no duplicate handler warnings).
- The very first load of the host (updating from 1.20 or older, or `omarchy plugin enable`) still needs one `omarchy-restart-shell`, because the running shell holds the old `BarWidget.qml` in memory.
