# OmaShaders: how it works and how to add effects

Full-screen GLSL effects over all monitors via Hyprland `decoration:screen_shader`.
They run inside the compositor on the GPU: no extra window, no CPU use, same cost on every monitor.

    bin/omashaders list | status | set NAME | off | toggle [NAME] | next | prev   (add -a to include animated) | animated [on|off|toggle] | gpu
    bin/omashaders effect [status|list|set NAME|off] | color [status|list|set NAME|off]
    bin/omashaders strength [effect|color|wall|mouse [N|+N|-N|reset]] | power [status|on|off|toggle] [--notify]

Effects live in `shaders/*.frag`, colour grades in `colors/*.frag` (GLSL ES 3.00, uniforms `tex`, `time`, input `v_texcoord`).
Validate with `glslangValidator -S frag shaders/NAME.frag`. Hyprland runs only one screen shader, so with an effect and a colour set,
`bin/compose-shader` merges them into `<state dir>/built/EFFECT@S+COLOR@S.frag` (effect first, the colour then reads the effect's result, each with its strength baked in as a constant because Hyprland has no custom uniforms);
`off` clears both, `effect off` / `color off` one layer. `set NAME` with a colour name sets the colour layer.
Hyprland 0.56 uses the Lua parser: the shader is set at runtime with `hyprctl eval`, `hyprctl keyword` does not work.

## Cost of animated shaders
Any shader that declares `uniform float time;` makes Hyprland show a red warning and need
`debug:damage_tracking = off`, which redraws the whole screen every frame (big GPU cost).
Static shaders must NOT declare `time`. Animated ones (Motion, plus hologram, matrix, fireflies, underwater, snowfall in Ambient)
are costly: `omashaders` sets `debug:damage_tracking=0` itself when an animated shader is applied
(no Hyprland warning) and back to 2 for static ones and for off. A warning left over from before is cleared with `hyprctl reload`.

## Adding a shader
Effect: drop `shaders/NAME.frag` with two comment lines right after `#version 300 es`: `// category: Lens|Retro|Devices|Art|Mood|Ambient|Motion` and `// desc: one line shown in the menu`.
Colour: `colors/NAME.frag`, category `Comfort|Color|Retro|Devices`; it must be a per-pixel function of `texture(tex, v_texcoord)` only (one such call, no other `v_texcoord`, no `gl_FragCoord`, no `time`), because the composer swaps that call for the effect's output and prefixes the colour's helper functions with `c_`.
Wallpaper and cursor strength (`strength-wall`, `strength-mouse` in the state dir) is the opacity of the overlay window over the real wallpaper / screen (`WallpaperFx.qml`, `MouseFx.qml`); for the cursor-bend effects `bin/cursor-bend` blends plain and bent screen with it inside the composed shader.

Themes are lines `screen|wall|mouse|color|name` in `<state dir>/themes` (the name is optional; `themeBase()` is the first four fields and is what saving, de-duplication and the current-theme mark compare). `renameTheme()` rewrites the line, `n` on the Themes menu and the IPC `themeRename N NAME` call it; the `starter-themes` file uses the same format.

Custom colours: the name `custom-RRGGBB` (any hex) is turned by `bin/compose-shader --custom STATE_DIR NAME` into a generated grade in `<state dir>/custom-colors/`, so favourites, themes and strength treat it like any shipped colour.

Strength: add `// strength: N` for the start value (default 100). By default the result is blended with the untouched screen (`mix(input, result, S)`), which is right for tints and overlays. Shaders whose look changes shape (pixel blocks, blur radius, curvature) add `// strength-mode: native` and read `STRENGTH` (0.0-1.0) themselves, so 0 % really is the original screen and the start value is readable.
Check everything with `bin/shader-check` (composes every effect and colour at 50 % and validates it with glslangValidator; standalone validation of a native shader fails on `STRENGTH`). Preview without touching the desktop: `bin/shader-preview IN.png SHADER.frag OUT.png [TIME]` (CPU rendering with Mesa; build the shader first with `bin/compose-shader`).

## Mixing two effects

`bin/compose-shader --fx2 FILE PCT stack|blend MIX` (and `--col2`) add a second layer. State: `effect2`, `color2`, `mix-effect`, `mix-color` (`MODE VALUE`); `bin/omashaders mix` edits them, `apply` passes them on and names the built file `fx@s+...` with a signature so mixes cache separately. The first layer cannot just be run twice, because an effect may sample `tex` at any UV, so layer A is rewritten into `vec4 fx_eval(vec2 uv)` (`v_texcoord` becomes the global `fx_uv`, `fragColor` the global `fx_o`) and in stack mode B's `texture(tex, ...)` calls become `fx_eval(...)`. Blend is `mix(fx_eval(v_texcoord), fy_eval(v_texcoord), share)`. `gl_FragCoord` is not remapped (the error is invisible). Colours are per-pixel on `fx_in`, so they simply run one after the other (stack) or are mixed (blend). Stack amount is the second's own strength; blend amount is the share of B and B then uses its remembered or start strength. `bin/cursor-bend` reads the same files, so bend shaders keep a mix. Window shaders mix too (1.17): `MIXWIN=1` makes `mixstate` read `effect2` / `color2` / `mix-*` from the scope (`window-effect2`, `window-mix-effect`, ... or `window-app/CLASS/...`, which `app_seed` copies), `window mix effect|color ...` runs the same `mix_run`, `window_file` passes `--fx2/--col2` and names the file with the mix signature, and `mix_summary` writes `window-mix` (TSV `SCOPE effect2 color2 emode eamt cmode camt`, `*` = All windows) for the menu. Setting a new window effect or colour clears its second. Wallpaper effects mix inside the shell: `wp-effect2` and `wp-mix` (`MODE VALUE`) are written by `Core.qml`; `WallpaperFx.qml` draws the second `FxLayer` over the first (stack: it samples a `ShaderEffectSource` of the first layer; blend: both sample the image) at opacity = amount, inside a `layer.enabled` item whose opacity is the wallpaper strength. `bin/shader-check` composes every effect and colour as the second layer in both modes.

## Window frames

`frames/*.frame` are presets of Hyprland's own shadow and border options (not GLSL; HyprWindowShade only paints inside the window). Format: `# category:`, `# desc:`, then `key=value` lines (colours `RRGGBBAA`; keys cover rounding, border size, active / inactive border, shadow range, power, colour, inactive colour, offset, scale, sharp, and `spin=SPEED`). `bin/frame-apply` (python3) reads `<state dir>/window-frame`, saves the current look once as `frame-base.json` (keyed by `HYPRLAND_INSTANCE_SIGNATURE`) and sends one `hyprctl eval 'hl.config({...})'`; an empty name restores that baseline. `spin` sets `hl.animation({leaf="borderangle", style="loop", bezier="linear"})`, which only starts after a focus event, so it re-focuses the active window (`hl.dsp.focus({window="address:..."})`). Gotchas: an unset `decoration:shadow:color_inactive` reads back as `ffffffff` and setting that explicitly gives white inactive shadows, so the active shadow colour is used instead; `hyprctl reload` drops runtime overrides, so the widget runs `window frame reload` (forget baseline, re-apply) on `configreloaded`. `listall` emits frames with section `frame`; the widget shows them as `f:` categories in the Windows column.

## Window shaders

`bin/compose-shader --window` builds the same merged shader for windows: `#version 320 es` and the result is multiplied by the window's own alpha (`vec4(rgb * a, a)`, the plugin expects premultiplied output), so rounded corners and transparent terminals stay intact. `bin/omashaders window ...` keeps the state (`window-effect`, `window-color`, `window-target`, `window-strength-*`, `window-applied`, `window-sig`) and calls `hl.plugin.HyprWindowShade.classshader(CLASS, FILE)` through `hyprctl eval` for every targeted app class, and `"clear"` for the ones it set before. Targets named `layer:NAMESPACE` (from `hyprctl layers -j`, listed by `window classes` after the app classes) go to `hl.plugin.HyprWindowShade.layershader(NAMESPACE, FILE)` instead, because bars, panels and overlays are layer surfaces; `*` includes them through `all_layers` (open layers + `ALL_LAYERS_KNOWN` pre-registered so a flyout is shaded from its first frame + layers shaded before; excluded: bar, background, wallpaper-fx, mouse overlay, lock preview, `*-dismiss`, `*-ghost`); the plugin's layer catch-all `*` is not used because it stacks with specific entries and cannot be overridden per layer. The widget also syncs on `openlayer`. The background/wallpaper/mouse overlay namespaces are not offered in the list. The OmaShaders menu is the shared `omarchy-keyboard-panel`, so it is shaded too; `window classes` prints the open classes then `all_layers` (so the menu is in the app picker even though its layer does not exist yet when the list is fetched), and `omashaders-bend-marker` is excluded like the other overlays. The window shader keeps the layer's alpha, so transparent margins stay transparent. Per-app settings: `window-app/CLASS/{effect,color,strength-effect,strength-color}` (the `WSCOPE` variable picks the directory, `window -a CLASS ...` sets it; `app_seed` copies the all-windows files on the first change). `window_apply` maps every target class to the all-windows file, then replaces the entry of each class that has an override (an override with no effect and colour removes it); `window-apps` is a TSV summary (`CLASS effect color effect% color%`) rewritten after each `window` command for the menu to watch. Built files live in `<state dir>/built-win/` and are deleted after 60 minutes only when no class uses them. Notes from testing on Hyprland 0.56: use `classshader` only (a window rule or tag created at runtime leaves a `shader:` tag that cannot be removed); a class is an exact match; a missing file is skipped silently and an already compiled shader stays cached until `reloadshaders()`; apply with `hyprctl eval`, `hyprctl dispatch` prints "expected a dispatcher" although it works. The widget calls `window sync` when a window opens while the target is *All windows*, and `window apply` at start. `bin/shader-check` also validates every effect and colour in window mode.

## Reacting to what moves on screen
Not possible inside a Hyprland screen shader: it gets only the current frame (no previous frame, no custom inputs), so it cannot compare frames. Possible variants: a cursor-reactive shader (a helper rewrites a constant and re-applies; recompiles each time, so only a few updates per second) or a Quickshell overlay with a screencopy feedback loop (heavy). Built since as the Bend cursor effects (below), though not as a frame-comparing shader.

## Wallpaper and cursor effects
`wallpaper-effects/NAME.frag` and `mouse-effects/NAME.frag` are Qt shaders; the compiled `.frag.qsb` next to each is committed so users need no build tools.
They are drawn by `WallpaperFx.qml` and `MouseFx.qml` in layer-shell windows (one per monitor) hosted by the first monitor's bar.
A new wallpaper effect file that the menu's built-in list does not know appears the next time the menu opens (no shell restart). Header lines: `// label:` (menu name), `// hint:` (grey text) and `// category:` (the group it is listed in: the name of an existing group such as `Weather and nature` adds it there, any other name creates a new group, no line puts it under "More"). `bin/omashaders listall` carries the category as the 7th column. The other menus (screen, colour, cursor, frames) already build their categories from the `// category:` header, so nothing needs QML edits.

Mouse reaction: every wallpaper shader that follows the pointer has its body in `fxMain(vec2 mpx)` and a shared `main()` wrapper that renders `fxMain(mouse)` at `react` = 1 (one pass), `fxMain(away)` at 0 (pointer far away, parallax uses the screen centre), and a mix of both in between (two passes; above 1 it extrapolates to exaggerate). The UBO ends `... cCream, cTarget, react, range` (Smoke has `tr0..tr3` after that), in the same order in `bin/wallpaper-preview`. `colorreact.frag` (Colour reactor) matches pixels to `cTarget` by OKLab distance (tolerance from `range`) and only those pixels are pulled toward the pointer, rippled and lit. State: `react-wall` (0-200), `wall-range` (0-100), `wall-target` (RRGGBB); `omashaders wallopt react|range|target`.
Speed and zoom (v1.18.0): speed is applied in `WallpaperFx.qml` (the `time` uniform is an effect clock that advances `speed` times real time; the trail sampler of `smoke` uses real time). Zoom is the shared vertex shader `wallpaper-effects/zoom.vert` (rebuilt by `bin/build-wallpaper-effects`), which scales `qt_TexCoord0` about the centre by `zoom`, and each fragment shader's `wall()` undoes that scaling when sampling the picture (`(uv-0.5)*zoom+0.5`), so only the effect scales and the wallpaper stays put (v1.18.1); new shaders must define `wall()` the same way; the pointer and trail uniforms are transformed the same way in QML. Every fragment shader declares `float zoom;` right after `float range;` (in the std140 padding, so later members like `tr0` keep their offsets) because Qt wants the vertex and fragment blocks to agree. New shaders must keep that line. State files `wall-speed` (0-300) and `wall-zoom` (25-300), CLI `omashaders wallopt speed|zoom`. `bin/wallpaper-preview` takes env `ZOOM` and `SPEED`.
Sprite effects (1.36.0): a wallpaper effect may draw painted sprites. Put `NAME.png` (RGBA atlas) next to `NAME.frag`, add `NAME` to `spriteEffects` in `WallpaperFx.qml` and declare `layout(binding = 2) uniform sampler2D sprites;` in the shader (binding 1 stays the wallpaper). `bin/wallpaper-preview` and `bin/wallpaper-overlay-scan` bind the PNG there too. `pumpkin-night` uses a 4x2 atlas of 256 px cells; the shader draws only the objects, never a scene. Wallpaper shaders are effects, pointer reactions and a few objects, not scenery: the user's own wallpaper is the scenery.

Several monitors: `MouseFx.qml` makes one overlay per monitor and passes `mouse` relative to that monitor, so on the other monitor it lies outside `0..res`. Dimming effects (`flashlight`, `spotlight`, `reading-line`) must keep their full dim there (never multiply the dim by "pointer is on this monitor", that darkens one monitor and lights the other and flashes when the pointer crosses); only glow and line effects may draw on the pointer's monitor alone. Dimming shaders read `float size;` (the Size setting) themselves and are listed in `selfSized` in `MouseFx.qml`, because scaling the whole overlay as a picture would uncover the edges. `tests/multi_monitor_check.py` renders them on two side by side monitors (venv: `~/Work/tools/omashaders-venv/bin/python`); `tests/vm-check-multi-monitor.sh` is the same on a real second monitor in the VM.

Recompile after editing with `bin/build-wallpaper-effects` / `bin/build-mouse-effects` (needs qt6-shadertools).
`bin/wallpaper-step next|prev|status|pick` steps or picks the wallpaper image; `bin/gpu-usage` prints `OVERALL SHELL HYPRLAND USED_MB TOTAL_MB`.
`bin/cursor-watch` prints the pointer position from the Hyprland socket (about 40 times a second) and exits when its parent exits.

### Wallpaper effects support, never scenery (1.48.0)

A wallpaper effect lies on top of the user's own picture and supports the mood of its theme with a shader, an abstract pattern or painted sprites. It never builds a picture of its own (a drawn room, cemetery, sea or landscape that replaces what the user set). Test: with the effect off the picture still carries the scene, with it on the mood changes.
- It reads the picture (colour, brightness, edges) and does something playful with it: recolours, lights, veils, bleeds, ripples. It has to look good on a forest, a city, a portrait and a plain gradient. "Only works with one wallpaper" is a reject. Themes should be universal because users pick other wallpapers for them.
- Gate: `bin/wallpaper-overlay-scan` must class the effect `overlay` (mean change <= 20, <= 40 % of pixels changed a lot) on a reference set of different pictures, frame time <= 2.5 ms at 1080p, no GLSL arrays, no "Failed to compile" in the shell log.
- Starter themes: every part is checked on the reference set, not only on the theme's own picture.
- `bin/theme-check` (no GPU) reads `wallpaper-effects/overlay.tsv`, fails when an effect has no row or when the number of `scene` effects is above `wallpaper-effects/scene-ceiling` (lower the number when effects are converted, never raise it), and lists the starter themes that still use a scene effect.

## A broken effect must never fill the disk or memory (1.41.1)
A shader the GPU driver refuses is retried on every frame and prints the whole shader into the shell log, which lives in a RAM disk, so a single bad effect can fill it and freeze the computer. Three layers stop that:
- `bin/fxcheck.py` (standard library only) tests a compiled `.frag.qsb` before it is drawn: missing, empty, damaged, cut off, not a Qt pack, wrong stage (a vertex pack is rejected by the renderer; `qsb` takes the stage from the **file extension**, so build from a file that ends in `.frag`, never `.tmp`) and, for sprite effects, the PNG. For AI-made effects it also extracts the GLSL ES 100 text from the pack and runs `glslangValidator` on it (a stricter dialect than the desktop one that `qsb` accepts; for example `clamp(int, int, int)` is refused by several drivers); skipped when those tools are missing. A file `fx-check-off` in the state dir turns the check off, only so the VM test can reach the guard behind it. `fxcheck.py repair DIR` rebuilds generated packs from their `.frag`; `bin/aigen.py` builds through `fxcheck.build_qsb`.
- `FxSafety.qml` (loaded through an `FxHost`, like the other sibling files; a sibling QML type cannot be used by name) asks `fxcheck.py` for each requested wallpaper, second wallpaper and cursor effect and only then lets `Core*.qml` hand it to `WallpaperFx` / `MouseFx`. A failed check, or `ShaderEffect.Error` from the renderer, calls `report()`: the setting is switched off once, one notice is shown, and a driver refusal is remembered in `fx-blocked.json` (keyed by the pack's modification time, so a rebuilt pack is tried again).
- `bin/fx-guard SHELL_PID SHELL_LOG STATE_DIR` (started by `FxSafety.qml`, standard library only) watches the shell log and memory. A shader error line, more than 20 MB of log in 60 s, more than 1.5 GB of memory growth in 60 s, or more than 600 MB in 30 s makes it print `trip ...` (the plugin switches every effect off); if the log or memory still grows 8 s later it clears the effect files itself, and 16 s later it restarts the shell. Its own log is `guard.log` in the state dir (under 64 KB).
Tests: `bin/fxcheck.py selftest`, `bin/fxguard_selftest.py`, `bin/aigen.py selftest`, and `tests/vm-check-fxguard.sh` (run from `vm-check.sh`: fake broken packs for every effect kind must switch off with one notice, at most 12 log lines and flat memory over 60 s).

## Bend cursor effects

`cursor-shaders/NAME.frag` defines `vec4 bend(vec2 uv)` and may use `CUR` (pointer, pixels, monitor-local), `CVEL` (pixels per second), `CT` (seconds since the pointer last moved), `RES` and `texture(tex, ...)`. Header lines: `// category: Bend`, `// desc: ...`, and `// tail: N` if the effect keeps changing for N seconds after the pointer stops. `bin/compose-shader --cur FILE` merges it with the Screen and Color layers (the Screen layer's `texture(tex, ...)` calls are redirected through the bend). `bin/cursor-bend` rewrites the `CUR`/`CVEL`/`CT`/`CMARK` constants and applies the file, at most 30 times a second; the multi-monitor marker is described in the README. Besides the pointer, a bend shader gets the trail: `CTR[8]` holds the 8 previous pointer positions (newest first, about 35 ms apart, monitor-local pixels). `cur_pt(i)` returns the trail point i (0 = pointer, up to 8) and `cur_seg(p, i, dir, len, h)` returns the distance from pixel `p` to trail segment i, with its direction, length and position h along it (see `// category: Follow` shaders such as `smudge.frag`). Use `// tail: 0.5` or more so the trail has time to collapse before updates stop. `bin/shader-check` validates every bend shader.

## Cost log and report

`bin/perf-log` (python3, started by the widget at load, one copy via `perf.lock`, re-execs itself when the file changes, stops with `perf-off`) appends JSON lines to `<state dir>/perf.jsonl`: `ev` start / change / sample / stop, `layers` (`screen:NAME`, `screen2:`, `color:`, `wall:`, `cursor:`, `win:`, `wincolor:`, `frame:`), strengths, `anim`, `gpu` (whole GPU %), `hypr` / `shell` (their SM % from `nvidia-smi pmon -c 2 -s u`), `hcpu` / `scpu` (CPU % from /proc), vram, watt, temp. Samples within 3 s of a change are marked `settle` and ignored. Cost of a layer = median of (hypr + shell) while it was on minus the median while nothing was on; layers only ever seen in combinations are averaged over those. `report` also writes `perf-report.md` and `perf-summary.tsv` (`kind name rating cost samples`, read by `omashaders listall` to append `[measured: ...]` to descriptions and by the widget for the active line). `bench` holds `bench.lock` so the sampler stays quiet, switches effects through `omashaders`, and restores the saved state files in a `finally`. Crash correlation uses `coredumpctl list --json` and the last log record before each crash; a start record without a preceding stop means the shell died uncleanly.


## Calm themes (v1.24.0)

- Starter themes 22-31 (Golden Porch, Misty Pines, Koi Pond, Lantern Night, Tide Pool, Snug Cabin, Lavender Dusk, Cloud Garden, Aurora Calm, Moon Lake) each add a static Screen shader, a Color grade, a wallpaper effect in the `// category: Calm scenes` group, a window-native shader and (all but Snug Cabin, which reuses `ice-crystals`) a new cursor overlay. Nothing new in the engine: the wallpaper group and the cursor entries come from the `// category:` headers, no `Core.qml` change.
- Design rules used: no `time` in screen or colour shaders (damage tracking stays on), start strengths 50-70, low contrast so text stays readable, no arrays in the Qt shaders, a window shader that is clearer on the focused window.

## Window-native shaders (v1.23.0)

- A shader in `shaders/` with the header line `// target: window` is a **window-native shader**: it is built only for the Windows column (`omashaders listall` prints it as section `winfx`; `names`, Screen, Surprise me and `set_shader` ignore it, `omashaders window effect list` includes it via `names -w`). Categories `Glass`, `Light`, `Living` are listed first in the Windows menu (`winfxEntries` in `Core.qml`) and are shown even when animated shaders are off.
- It may declare the HyprWindowShade uniforms `surface_size` (vec2), `is_active`, `is_floating`, `is_fullscreen`, `seed` (floats), `mouse` (vec2, compositor px), `window_box` (vec4, compositor px), `resolution` (vec2), `velocity` (vec2) and `is_moving`, each on its own `uniform TYPE NAME;` line. `bin/compose-shader --window` strips those lines from the layers, declares them once in the prelude and never renames them (`PLUGIN_UNIFORMS`). Pointer position inside the window: `(mouse - window_box.xy) / window_box.zw`. `time` works as everywhere. Use pixel units (`v_texcoord * surface_size`) so patterns keep their size when a window is resized. The composer multiplies the result by the window's alpha, so transparent margins stay transparent.
- `bin/window-preview IN.png NAME OUT.png [TIME] [STRENGTH] [COLOR]` composes and renders one on the CPU; `bin/shader-preview` sets test values for the plugin uniforms and takes overrides from `U_name=...` variables (`U_is_active=0 U_mouse=300,200 U_seed=0.8`). `bin/shader-check` builds window-native shaders with `--window` and leaves them out of the screen, bend and mix loops.
- Starter themes 17-21 (Detective Hour, Dappled Grove, Hearth Night, Observatory, Mainframe) each ship a window-native shader (`venetian-blinds`, `leaf-shade`, `firelight`, `starglass`, `crt-monitor`) plus a new Screen shader and Color grade; a user without the HyprWindowShade plugin simply sees the rest of the theme.

## Themes, fullscreen pause, cursor size and speed, audio effects (v1.22.0)

- **Theme lines** (`themes` / `starter-themes`): `screen|wall|mouse|color` or `...|name` or `...|name|winEffect|winColor|winFrame`. A line without the window fields turns the Windows effect, colour and frame off when applied (an empty part is always empty); a line with them sets Windows effect, colour and frame for all windows (`omashaders window ...`, run one after the other in one shell so the plugin sees a consistent state). `themeBase()` is the identity of a theme (name removed); a saved 4-part line still matches while the live Windows settings differ.
- **Pause while fullscreen:** state file `pause-fullscreen` (setting, `omashaders fullscreen on|off|toggle|status`) and `fs-paused` (comma list of Hyprland monitor ids, set by `omashaders fullscreen pause IDS`, cleared by `resume`). It is per monitor: `is_disabled` only follows the manual `disabled` file; `apply` passes `--skip IDS` to `bin/compose-shader`, which makes the composed screen shader return the plain picture when the `wl_output` uniform (Hyprland feeds it the monitor id) is in the list, so one global `screen_shader` still behaves per monitor (the built file name carries `!IDS`). `bin/cursor-bend` reads the same files for its shader. Window shaders and frames are not paused (HyprWindowShade drops shaders on a fullscreen window itself; frames have no border or shadow on one). `bin/fullscreen-watch` (python) follows Hyprland's event socket (`.socket2.sock`) and prints "ID:NAME ID:NAME" for the monitors whose active workspace `hasfullscreen` (`j/monitors` + `j/workspaces`), or `-`, once at start and on every fullscreen / workspace / focus / window event; Core turns that into `fsMonitors`: `fsOffScreens` (names) is passed to WallpaperFx / MouseFx, which leave those screens out of their per-screen windows, and `fsIds` triggers `fullscreen pause IDS|resume`. Core runs `fullscreen resume` at load so a leftover flag never sticks.
- **Cursor Size and Speed:** state files `mouse-size` (25-300) and `mouse-speed` (0-300), CLI `omashaders mouseopt size|speed`, sliders under the Cursor strength slider, keys `z`/`Z` and `v`/`V`. `MouseFx.qml` scales the overlay item about the pointer (`Scale` transform, so cursor shaders must compute in pixel units from `qt_TexCoord0 * res`, `mouse` and `h0..h3`, never `gl_FragCoord`) and advances `time` at `speed` times real time. Bend effects ignore both (they are screen shaders rewritten by `bin/cursor-bend`).
- **Cursor trail history (v1.38):** `MouseFx.qml` keeps 16 pointer samples, one every `histStep` = 0.066 s (about one second back), and gives a cursor shader `h0..h7` (sample 1 = `h0.xy`, sample 2 = `h0.zw`, ... sample 16 = `h7.zw`; `mouse` is the live pointer) and `hs` = (sequence number of the newest sample, phase 0-1 since it was taken, step in seconds, 0). The history must store copies of the pointer (`Qt.point(x, y)`): a `point` pushed into a JS array as is stays tied to the live `mouse` property, so every sample followed the pointer and trails never existed (found in the VM, `tests/vm-check-trail.sh` fails on that). Trail effects must not seed anything by slot index: a sample keeps its place and moves to the next slot every 0.066 s, so a random look tied to the slot makes every particle jump ("flashes around the pointer"). Use `SID(i) = mod(hs.x - float(i) + 1.0, 4096.0)` for hashes and `AGE(i) = (float(i) - 1.0 + hs.y) / 16.0` (0 at the pointer, grows continuously, 1 when the sample is dropped; fade to 0 there). Emit only from samples that themselves moved (`distance(P(i), P(i+1))`), never gate by the distance to the live pointer. Shaders that only declare `h0..h3` keep working (they see the newest 8 samples). `tests/trail_check.py` renders a cursor shader offline (moderngl, EGL) along a slow stroke and prints reach behind the pointer and frame-to-frame jumpiness; `strip` writes a picture strip.
- **Audio-reactive effects:** a wallpaper or cursor effect whose id starts with `audio-` makes the shell run `bin/audio-level` (python3 + numpy + `parec` from the default sink's monitor, 16 kHz mono, 40 ms windows; prints `level bass mid treble`, each 0-1, auto-scaled with a slow peak follower, fast attack and slower release; `--stdin` reads raw s16le for tests). It stops when no such effect is on. `WallpaperFx.qml` and `MouseFx.qml` expose `audio`, `bass`, `mid`, `treble`; a shader reads them by declaring `float audio; float bass; float mid; float treble;` at the END of its uniform block (Qt maps ShaderEffect properties to uniform members by name; shaders without the members ignore them). In silence all four are 0, so audio effects need a calm idle look. `bin/wallpaper-preview` packs the UBO in a fixed order, so a test copy has to append the four floats.
- Hyprland screen shaders cannot receive audio (and `cursor-bend` rewrites the shader file, which is too heavy at audio rates), so in an audio-reactive theme only the Wallpaper and Cursor pieces move with the sound.

## Hot reload (v1.21.0)

Nothing in this plugin needs `omarchy-restart-shell` while you work on it, except changes to `BarWidget.qml` itself (and `manifest.json`).

- New or edited files in `shaders/`, `colors/`, `wallpaper-effects/`, `cursor-shaders/`, `mouse-effects/`, `frames/` and `bin/` are read again the next time the menu opens (new wallpaper categories come from `// category:`).
- QML: Omarchy loads `BarWidget.qml` once at shell start, so it is only a thin host. The real code is `Core.qml` (what `BarWidget.qml` was before 1.21). The host watches `Core.qml`, `WallpaperFx.qml`, `MouseFx.qml` and `BendMarker.qml` (FileView) and, 0.4 s after a change, compiles all four with a new `?v=` query string (Qt caches components by URL, so the query defeats the cache), then destroys the running Core and creates the new one 0.15 s later (`createObject(root, {host: root, ver: ver})`; the gap lets the old IPC handler and helper processes go first). Core's `bar`, `settings`, `moduleName` and `setting()` come from the host, the host forwards `opened`, `open()`, `close()`, `toggle()` and `closeForPopoutSwitch()` that the bar calls. If any of the four files has an error the swap is refused: the old Core keeps running, the host logs `OmaShaders: not reloading ...`, sends a desktop notification and shows a red `!` on the bar icon until the next good save. Sibling QML files are loaded from Core through `FxHost` loaders with `root.sub("File.qml")` (versioned url); a new sibling QML file must be loaded the same way and added to `files` in `BarWidget.qml`, never as a plain type name inside Core.qml. A reload closes an open menu and restarts the helper processes and wallpaper/cursor windows (a short flicker); all state is in files, so nothing is lost.
- Two menus: the host reads the plugin setting `menuLayout`. `Classic` runs `CoreClassic.qml`, the 1.36 menu (Screen, Color, Wallpaper, Cursor, Windows, Combos) kept as it was; its saved list is the `themes` file and its starter list is `starter-themes`. `New` (default) runs `Core.qml` (themes layout, AI, Share, Wallhaven). Both share `WallpaperFx.qml`, `MouseFx.qml`, `BendMarker.qml` and `bin/`. The host watches only the files of the layout in use and `status` prints `layout=classic|new`; switching the setting reloads. A fix in the shared behaviour (for example the fullscreen pause) has to go into both Core files. `vm-check.sh` switches to New first; `tests/vm-check-classic.sh` sets Classic and tests it.
- `omarchy-shell io.github.akton1.omashaders-host reload` forces a reload, `... status` prints `reloads=N running=yes|no error=none|first error line` (use it in scripts and tests).
- Omarchy has its own hot reload (any save under `~/.config/omarchy/plugins/`, found by `inotifywait -r`), but it does not follow symlinks, so a plugin installed with `ln -s` from a source tree never triggers it; that is why the host has its own watcher. With a real directory (store install, `cp`) Omarchy's reload fires instead: it rebuilds every plugin widget, so the host and its Core are recreated from scratch. A broken edit then removes the icon (only the red `!` stays) until fixed. For development use the symlink layout.
- A watcher `FileView` on four files costs nothing for people who never edit the plugin.
- `vm-check.sh` (run by `vm-test omashaders`) proves all of this in the Omarchy VM in both layouts: edit the bar glyph, broken edit refused, restore, broken sibling, new wallpaper categories in the open menu, an edited menu string, forced reloads (no memory growth, one perf-log, no duplicate handler warnings).
- Left list of each menu (1.41): `SectionMenu` in `Core.qml` gets its rows from `menuBuild()` (block between `// menulist:begin` and `// menulist:end` near `rowGlyph`): commands (`action: true`) become a fixed button block, a filter adds an `All matches` row (flat, each result names its category) and then the categories that match, with counts. `python3 bin/menulist_selftest.py` runs that block under node (14 checks, skipped without node); `tests/vm-check-menus.sh` takes the screenshots. Classic (`CoreClassic.qml`) is unchanged. Do not move the block into a new `.js` file: Qt caches the folder listing, so a shell that started before the update refuses the new file (`Script ... unavailable`) and the update would not load until `omarchy-restart-shell`.
- `tests/vm-check-invent.sh` checks Invent mode in the VM (fake AI command, Keep/Discard, nothing in the plugin folder). It needs its own run because `vm-test` gives a plugin check 300 s and `vm-check.sh` already uses most of it: `d=$(mktemp -d) && cp -r . "$d" && cp "$d/tests/vm-check-invent.sh" "$d/vm-check.sh" && vm-test "$d"`. It installs `python-pillow` and `python-numpy` in the throwaway VM (stock Omarchy has neither); the gate and flow self-tests (`python3 bin/aigen.py selftest`, `python3 bin/aiinvent_selftest.py`) run on the host and skip their render parts when those packages are missing.
- The very first load of the host (updating from 1.20 or older, or `omarchy plugin enable`) still needs one `omarchy-restart-shell`, because the running shell holds the old `BarWidget.qml` in memory.

### Record GIF (v1.29.0)

- `bin/gif-capture` (python3, no dependencies; `omashaders gif ...` calls it) does everything outside QML. `Core.qml` only has the `@gif` action row, the `I` key, `recordGif()`, the IPC functions `gif` and `gifCount N MONITOR`, and the countdown layer (`omashaders-gif-countdown`, overlay, `WlrKeyboardFocus.Exclusive` so `Esc` works, empty input mask). `Esc` runs `gif-capture cancel` (touches a file the script polls).
- Timing (1.33): `start_demo` opens the terminal early, places it and parks it on the workspace `omashaders-gif-stage` (`hl.dsp.window.move({workspace="name:...", follow=false})`); the recording starts with the bare wallpaper and `sweep(..., at=0.75, on_at=open_demo)` calls `show_demo` (move back + focus, then the `go` file) in a thread when the eased progress reaches 0.75, so the pointer never stalls. `cursor:no_warps` is on for the whole recording (focusing the terminal would warp the pointer to its centre) and the old value is kept in the restore file. The tail is the session length (`gif-demo --duration`) plus 0.8 s. The pointer path (`SWEEP_WAYPOINTS`) is an S along the bottom and a climb at x 0.76 to 0.86 of the width, i.e. through the right part of the terminal, so pointer-reactive window shaders (`crt-monitor` glow) react; before, it stayed outside the terminal's edge.
- Clean picture: `start_demo` opens a terminal (alacritty, else kitty, else foot) with class `omashaders-demo`, a generated config (fixed palette, font, opacity) and runs `bin/gif-demo` in it (the last command is made up by the AI of the theme creator: `gif-demo --prepare` is started by `cmd_gif` early, writes `flavour.json` in the work dir, and the session and `--duration` read it; without an AI it falls back to a command around a word of the name; the scripted session: parts read from the state files, 12 steps/s, started by a `go` file that `cmd_gif` creates right before the recording). `place_demo` floats it as the 840x368 rounded box at (60, 85) of a 960x540 picture (`DEMO_BOX`, scaled by `min(lw/960, lh/540)` and centred), with rounding/border set by the `hl.dsp.window.set_prop` dispatcher (`hyprctl setprop` is gone in Hyprland 0.56), so the wallpaper stays visible around it (the look of `abyss-preview-theme-terminal-v2.gif`); foot >= 1.25 takes its colours from `[colors-dark]`, and adds that class to `window-target` when the window effect is limited to some apps (removed in `restore`). `Watch` polls `hyprctl layers`/`clients` every 0.2 s during the recording; any layer not in `OWN_LAYERS` or window other than the demo terminal raises `Unclean` and no GIF is made. `tests/vm-check-gif-clean.sh` opens a foreign layer from another process (the VM has none of its own) and checks both outcomes.
- Hiding: the pointer's monitor goes to the empty named workspace `omashaders-gif` (windows are not moved or touched), the bar via the flag file `~/.local/state/omarchy/toggles/bar-off` plus `omarchy-shell -q omarchy.bar syncHidden`, notifications via `omarchy-shell notifications setDnd`. State needed to undo it is written to `~/.local/state/omarchy/omashaders/gif-restore.json` first; `restore()` always runs (try/finally, SIGTERM/SIGHUP, `omashaders gif restore`, and at shell start from `Component.onCompleted`).
- Restore order matters: close the countdown layer first (its exclusive focus unmapping otherwise re-focuses some window), set `cursor:no_warps` for the duration, move the pointer back before focusing the old window, focus the window last. Without this the focus ended on the wrong window or the pointer jumped.
- Moving the pointer: `hyprctl dispatch` takes Lua here, so a cursor move is `hl.dsp.cursor.move({x=,y=})`; the sweep writes `dispatch hl.dsp.cursor.move(...)` straight to Hyprland's command socket (a `hyprctl` process per step is too slow). Coordinates are logical (monitor pixels / scale). The path is one S (`sweep_point` in `bin/gif-capture`): ease-in-out progress along the diagonal from bottom left to top right plus a sine offset perpendicular to it (amplitude 0.24 of the short side), over about 1.5 s by default.
- Recorder order: `gpu-screen-recorder` (SIGINT stops it), `wf-recorder`, `grim` (thread grabbing PPM frames). If the first one does not start (for example no GL) the script falls back to grim. Encode ladders `LADDER` and `SHARE_LADDER` in the script, each rung (width, fps, palette colours; the share ladder keeps 12 fps and shrinks picture and border together instead of dropping to 6 fps at 960 px, the code decodes down to 560 px even at the 5.4 KB maximum; cost is about proportional to pixels x frames, a full-screen moving shader costs 150-230 KB per 960x540 frame, border noise is almost free); the first 0.1 s of a video recording are cut.
- Lessons: an empty `disabled` file means effects are on (only non-empty counts as paused). Notifications made while hiding show up in the capture, so the "done" message is sent after restore.
- Testing: do not hide windows on the real desktop. Use `vm-test` / `omarchy-vm run` (one user of the VM at a time). `gpu-screen-recorder` cannot run in the VM (no hardware GL), so the grim path is what gets tested there; the real gsr path and timing (`LEAD`, `TAIL`) have to be checked once on real hardware. Check a result with `ffmpeg -i X.gif -vf "fps=4,tile=4x2" sheet.png` (bar absent, no windows, cursor effect visible). `--recorder grim|wf|gsr` forces a backend, `--countdown N` shortens the wait.

### Background theme jobs (v1.35.0)

- Why: a theme took minutes and lived in the dialog's `Process`; Esc, closing the menu or a shell reload killed it and the result was lost. Now every AI turn is a job whose state is a folder, `<state>/jobs/<id>/` (`job.json`, `chat.json` (the chat session of that job), `rich/`, `runner.log`, `cancel` marker). Nothing depends on a QML `Process`; QML only starts commands and polls.
- `bin/aijobs.py` (CLI through `ai-theme job ...` and `omashaders theme jobs|job`): `start` (Popen of `ai-theme job _run ID` with `start_new_session=True`, inside `systemd-run --user --scope --collect --unit=omashaders-job-ID` when `scope_ok()`, else plain setsid; `OMASHADERS_JOBS_NO_SCOPE=1` forces setsid), `change` (a second turn on the same job = same chat), `retry`, `cancel`, `save`, `discard`, `dismiss`, `list`, `show`, `form get|set` (the typed prompt, mode, rounds, parts; also saved when the dialog hides on the form). At most `MAX_JOBS` (2) live jobs; a third is refused with a plain message.
- The runner (`_run`) is the only writer of `job.json` while the job runs (per-job flock, atomic tmp + replace). It runs `ai-theme chat turn ... --json` as a child (PDEATHSIG, so it dies with the runner), turns the `PROGRESS` lines on stderr into `step` / `progress`, stores `result`, `history`, `turn`, and sends the notification (`notify-send`; `OMASHADERS_NOTIFY_CMD` replaces it in tests). Per-job isolation is the env var `OMASHADERS_CHAT_DIR`, read at call time by `aichat.chat_dir()` and `airich.rich_dir()`; the old single chat in the state folder is just the default of that variable. `aigen.install` takes a flock on `generated/.lock`, so two jobs installing effects do not clash.
- States: `starting`, `running`, `done` (a draft: `has_result`), `failed`, `interrupted`, `cancelled`. Liveness is pid + `boot_id` + `/proc/<pid>/stat` start ticks, so a pid reused after a reboot is not mistaken for the runner; `view()` shows a job that says running but has no runner as `interrupted` (also the case after a reboot), and `retry` runs it again. `failed`/`interrupted` with a prior draft keep the draft (the Change turn failed, the draft is intact). `cancelled` is hidden in the UI and pruned after an hour.
- Cancel is explicit only: the `cancel` marker, `systemctl --user stop` of the scope, then `killpg(getpgid(pid))` TERM and KILL, then the state is written. With a prior draft the job goes back to `done` ("The change was cancelled."), without one it becomes `cancelled`. The dialog never calls cancel on close; its Cancel job button needs two clicks.
- QML: `Core.qml` polls `aijobs.py list --json` (every 2 s while a job runs, every 12 s otherwise; `jobs`, `jobRows`, `jobClock`, `jobLook`), draws the busy dot on the bar icon (`// bar-icon`), the Themes rows (`@job:<id>`, text bound to `jobRowText`, rows rebuilt only when the job set or a state changes) and the tooltip line. `openDialog(mode, whId, number, jobId)` opens the dialog on a job. `ThemeDialog.qml` attaches by `jobId` (a running job first, then a draft, then one that stopped), shows `jobStatus`, runs its commands through `runJob` (one `ai-theme job ... --json` at a time), and previews a finished draft with `showDraft()` and puts the old look back in `leaveLook()` when it hides. A draft is never applied while no dialog is open.
- Known limits: effects generated by a turn that was cancelled or killed mid-way stay in `generated/` as pending effects (nothing sweeps them; `aigen.py list` shows them, `ai-theme discard ID` deletes one); the step total ("step 3/6") is a guess from `STEPS` that grows if a run needs more; a job is not resumed after interruption, Retry starts the turn again (and pays again).
- Tests: `python3 bin/aijobs_selftest.py` (scratch state, a fake AI shell script and a fake notify command; runs once with setsid and once with a systemd scope; proves: the job runs on after the starter is gone, the draft is not in the list until saved, a notification names where to find it, Change on a draft, a killed runner shows as interrupted and Retry works, cancel kills the whole run including the AI child and only through `job cancel`, two jobs at most, the form comes back). It is part of `ai-theme selftest`. `tests/vm-check-jobs.sh` drives the real dialog in the VM with the Rich fake AI: Esc and a shell restart mid-run, the draft after reopening, an interrupted job, an explicit cancel (run it as its own vm-test; see the header). `vm-check-invent.sh` and `vm-check-rich.sh` now look for the session in the job folder.

## Palettes (1.39)

A palette is a colour grade described by numbers, not a shader file. Its name is `pal-` plus hex digits (layout in the header of `bin/omspalette.py`), so favourites, themes, share codes, strengths and per-app windows treat it like any grade. `bin/compose-shader` turns the name into a generated shader (`omspalette.glsl`) in `<state>/custom-colors/` on first use, like `custom-RRGGBB`; `omslib.pick_id` and `theme-code` accept well-formed ids only (`omspalette.is_palette_id`: length and stop count are checked, nothing else is ever put into a shader). Order of the maths: saturation and contrast, shadow/light tint (a luma-neutral multiplier), the brightness ramp (piecewise linear on `pow(luma, gamma)`), mix with the original by "keep", flat levels. `omspalette.render` is a numpy copy of the shader; `bin/omspalette_selftest.py` compares it with a real Mesa render. `palette.js` (used by `PaletteDialog.qml`) is a JavaScript copy of encode/decode; `bin/palette_js_selftest.py` checks it writes and reads the same ids as Python. The editor applies the colour name through `applyColor` at most every 220 ms while you edit (a timer that starts, not restarts, on a change, so dragging a slider updates the screen as you go). `bin/palette-fit` fits every built-in grade to a palette and measures the difference (`palettes/presets.tsv` is its result, `docs/palette-coverage.md` the report with the engine gaps: a 3x3 colour matrix after the ramp would reproduce the most extra grades). VM check: `tests/vm-check-palette.sh`.
- Changed look, Revert, Undo (v1.42.0): `themeOrigin` (set by `applyTheme`, `saveTheme`, `replaceOrigin`, and by `adoptOrigin` at start when the look equals a saved theme) names the theme the look came from; `lookChanged` is true when the look (effects, window parts and the strengths/speed/zoom the origin line stores, `optsDiffer`) no longer equals it and equals no other saved theme (and not while `optsTimer` is still applying a theme's numbers). It only drives labels: "(changed)" on the origin row, in the Themes header and in the bar tooltip, plus rows `@saveas` / `@revert` / `@undo` and keys `b` / `y`. Nothing is written or copied until a save. `applyTheme` stores the look it replaces in `undoLine` when `lookChanged` (so Revert and picking another theme are both undoable; `undoDrop` restores it and the origin; cleared after 3 minutes). `replaceOrigin` now also overwrites the user's own origin theme (built-in only with the dev switch). A look the user changed in an effect never edits a built-in effect: there is no in-place effect editor, Create with AI saves a new `ai-*` effect and the palette editor makes a new `pal-` id. `ipc look` prints `none|same|changed` plus the origin name. `CoreClassic.qml` untouched. VM check: `tests/vm-check-changed.sh` (own `vm-test`; it precompiles `bin/` first, because a `__pycache__` written into the plugin folder makes the shell reload the plugin and forget the origin).

## Theme categories (v1.43.0)

- The Themes column lists `All themes`, `Surprise me`, then one group per category (`themeCatGroups` in `Core.qml`), then the commands. A group is a normal `menuBuild` category (id `cat:NAME`, `badge` = count), so the filter, number keys and hover preview work unchanged.
- Built-in grouping: file `starter-theme-categories`, lines `Category|Theme name` (order of first appearance = menu order; a built-in theme without a name or entry lands in `More`). `python3 bin/themecats_selftest.py` checks it against `starter-themes`; a new starter theme needs a line there. Not in the Classic menu (`CoreClassic.qml`).
- Your own: state file `theme-categories`, lines `cat<TAB>Name` (a category you made, may be empty) and `set<TAB>Name<TAB>theme base` (a theme moved by hand; keyed by `themeBase()`, so renaming or re-saving the theme keeps its place and a duplicate starts in the same category). A saved theme with no entry is in `My themes`. `themeCategory(line)` is the one lookup.
- UI: `K` / `M` (and the commands New category / Move to category) reuse the rename field below the columns through `catMode` (`new` | `move`); in `move` Tab and the arrow keys cycle `catChoices`. `Delete` with the cursor on one of your categories asks twice (`deleteCategoryAsk`).
- VM check: `tests/vm-check-categories.sh` (copy it to `vm-check.sh` in a scratch folder for `vm-test`).
- VM check: `tests/vm-check-theme-menu-stays.sh` (same way) covers the Themes menu staying on its category, row and both scroll positions while a theme is chosen (it samples the menu during the change and counts jumps of a list to its top; the menu fitting a different number of rows afterwards is not compared). `omarchy-shell io.github.akton1.omashaders themeMenu` prints the state it compares.
- Last picker, F3 and heights (each its own `vm-test`, same way): `tests/vm-check-lastview.sh` (Create with AI / Wallhaven / Palette are remembered when the menu is dismissed, Esc clears it, survives a shell reload, a junk `last-view` opens the main menu; `omarchy-shell io.github.akton1.omashaders view` prints the state), `tests/vm-check-resources.sh` (F3 hides / shows the GPU block, the poll stops, rows grow, state file `resources`, survives reload; IPC `resources`), `tests/vm-check-height.sh` (the card fits the room and the lists fill it at 1280x800 up to 4K, a theme choice keeps rows and scroll; a size the software-rendered VM cannot draw is reported as SKIP). A picker is left with `leave()` (Esc, q, Close: forgets it) and dismissed with `close()` (click away, bar icon: `core.hideViews(true)` keeps it); a new dialog file must follow the same split.
