# OmaShaders

<a href='https://ko-fi.com/akton1' target='_blank'><img height='36' style='border:0px;height:36px;' src='https://storage.ko-fi.com/cdn/kofi3.png?v=6' border='0' alt='Buy Me a Coffee at ko-fi.com' /></a>

Shader effects for the [Omarchy](https://omarchy.org/) desktop, from one bar icon: over 100 screen and window shaders (CRT, pixel art, e-ink, Game Boy, camouflage, halation, oil paint, matrix rain ...), over 130 colour grades plus your own custom colour, about 170 animated wallpaper effects (a slider sets how much they follow the mouse; one reacts only to a colour you pick), more than 50 cursor effects (trails, glows, rain ripples, plus ones that bend the real screen under the pointer), and 156 ready-made themes that set everything together. Hover to preview, click to keep, and a strength slider on every menu that starts at a value where text stays readable.

> **Brand new: this plugin is five days old** (first written on 9 October 2026, first public release on 10 October 2026, this update on 14 October 2026). Most of it has only been tried by its author on one machine (NVIDIA GPU, two monitors). Expect rough edges, effects that change or get renamed, and settings that move between versions. Bug reports are welcome.

## Install

```
omarchy plugin add https://github.com/AktOn1/omashaders.git --enable
```

Then add the **OmaShaders** widget (monitor icon) to your bar in the Omarchy shell settings. Restart the shell once (`omarchy-restart-shell`) if the icon does not appear.

## Requirements

- Omarchy with the shell plugin system and Hyprland 0.56 or newer (Lua config). The screen effects are set with `hyprctl eval`.
- `python` 3 and `bash`. For the wallpaper picker: Omarchy's own `omarchy-menu-images` and `omarchy-theme-bg-set`.
- Optional, for the audio-reactive effects (ids starting with `audio-`): `python-numpy` and `parec` (pipewire-pulse). Without them those effects just stay still.
- Optional, for **Invent new effects** (AI themes): `python-pillow`, `python-numpy`, `glslang` and `qt6-shadertools`. The safety check renders every new shader offscreen before it can be used, so without them the dialog keeps Invent switched off, says what to install, and nothing is sent to the AI. Pick existing effects needs none of them.
- Optional, for the Wallhaven browser: `curl`. Optional, for AI themes: one of the `claude`, `codex`, `gemini`, `opencode` or `ollama` commands, or any AI command you set (see AI themes), and ImageMagick (`magick`) when a picture is sent. Optional, for share codes: `wl-clipboard` (`wl-copy`, `wl-paste`).
- Optional, for **Record GIF**: `ffmpeg` and a screen recorder: `gpu-screen-recorder` (the one behind Omarchy's screen recording; used first), else `wf-recorder`, else `grim` (works anywhere, but only about 5 to 10 frames a second). Also `wl-clipboard` (the GIF is copied) and `libnotify` (`notify-send`, the message when it is done). Without `ffmpeg` or a recorder the button just says what to install.
- Optional: `nvidia-smi` (NVIDIA) for the GPU line in the menu footer; on AMD it is read from sysfs. Without either the line is empty.
- No build tools are needed: the compiled wallpaper and cursor shaders (`.frag.qsb`) are included.

## First run

1. Click the monitor icon in the bar. The **Themes** column opens on the left: pick a complete look first (hover to preview). On the right, the **Effects** pane always lists five groups (**Screen**, **Color**, **Wallpaper**, **Cursor**, **Windows**) as folded headers that show what is on in each; click one to open it with all its settings, and the one that was open folds. The menu uses the full height of the screen.
2. Move with `h j k l` or the arrow keys. Moving onto an effect with the keys previews it live; hovering with the mouse only highlights it; hold `Shift` while hovering to preview, and the previous setting comes back when you release Shift or move off the item (a click keeps it). Categories (left column) are never selected by hovering; click one.
3. `Enter` keeps the effect and closes, `Space` keeps it and stays open, a click keeps it and stays open, `Esc` puts everything back as it was.
4. Pick an effect and a colour together: the effect runs first, then the colour grade is applied to its result (for example `crt` + `gameboy` is a CRT look in Game Boy greens).
5. Lower the **Strength** slider if an effect is too strong. Every effect starts at a readable value (pixelate 20 %, Game Boy LCD 25 %, C64 25 % ...); 0 % is the original screen.

## Usage

Bar icon: **left click** menu, **right click** pause / resume all effects (they come back exactly as they were), **middle click** next wallpaper, **scroll** steps the screen effect.

The menu has two steps. **1 Pick a complete theme** on the left (hover to preview, `Enter` keeps it). **2 Fine-tune the effects** on the right: the Effects pane lists Screen, Color, Wallpaper, Cursor and Windows as headers that are always visible, folded or open. Each folded header says what is on in that group; click it (or press the group's key) to open it with all its settings (strength, mixing, options), which closes the one that was open. The open group is remembered. **Surprise me** is a category in the Themes pane: a random complete theme, a surprise for everything, or only for Screen, Color, Wallpaper, Cursor or Windows; *Clear everything* is there too. At the top left, the line "Screen black or laggy? Press p" is followed by the big **Pause all effects** button (key `p`) and the *Pause in fullscreen* box. Below the columns, **What is using my GPU** lists everything that is on in plain words (green light, yellow medium, red heavy), says in one sentence what to switch off if the system lags (click a chip to switch that effect off) and how busy the graphics card is. The detailed cost report is command line only (`omashaders perf report`). The bottom of the menu has a **Hotkeys** button (key `?`) that unfolds every hotkey; folded, it shows just the few you need first. **Ctrl+Alt+P** pauses and resumes everything from anywhere (the plugin binds it in Hyprland when the shell starts; see *Pause key* below), and the menu shows it, so you know what to press when the screen has gone black. **Save** (`F`) and **Share** (`S`) open a small window each; they are not rows in the Themes list any more.

### Mixing two effects (1.12)

Hold **Ctrl** while you pick (`Ctrl+Enter`, or `Ctrl+click`) a second effect in the Screen, Wallpaper or Windows menu, or a second grade in the Color or Windows menu (1.17 added Wallpaper and Windows; a window mix belongs to the app you are editing). The first stays; the second is marked `+ stack` / `+ blend`, and a **Mix** row appears under the strength slider. Picking the second again with Ctrl removes it.

- **Stack:** the second runs on the result of the first, and the Mix slider is the second one's strength (pixelate under a CRT, an amber grade on top of a duotone ...).
- **Blend:** both run on the original picture and the slider is the share of the second (0 % = only the first, 100 % = only the second).

Click the mode name (or press `t`) to flip between them. Both layers are merged into the same single shader Hyprland runs, so a mix costs about the sum of both effects; mixing an animated effect needs the same `debug:damage_tracking=0` as any animated one. While a mix is on, hover and key-move previews are off so they cannot throw it away; choosing any item normally replaces both, and so do Surprise me, Off and Themes (themes do not store a mix). The Cursor menu does not mix. A wallpaper mix is drawn by the shell as two layers (the second reads the first one's picture in stack mode), so it costs about both effects. Command line: `omashaders mix effect|color status|set NAME|off|mode stack|blend|toggle|amount N|+N|-N|reset`, and for windows `omashaders window [-a CLASS] mix effect|color ...` the same way.

### Animated effects

Effects that move (grain, scan-sweep, vhs, heat-haze, glitch, hologram, matrix, fireflies, underwater, snowfall and a few more) need Hyprland's damage tracking switched off, which redraws the whole screen every frame and **raises GPU use a lot**. They are hidden until you press `a` (or turn on the setting below). While one is on, the plugin sets `debug:damage_tracking=0` itself so Hyprland shows no warning, and sets it back for static effects and for off. Static effects cost almost nothing.

### What is on, and what it costs (1.14)

At the bottom of each column an **ON:** row lists what is active in that column (Screen: effect and its mix; Color: grade and its mix; Wallpaper: effect and its mix; Cursor; Windows: effect, colour, frame, and each app or panel with its own window setting) as clickable chips: **click a chip to switch just that one off** (an app's chip removes its own setting, so it follows All windows again; clearing the main screen or colour chip also clears its mix). Windows shaders on All windows also reach shell panels, so this menu and other plugin flyouts are shaded too. While the plugin runs it also keeps a small log, `perf.jsonl` in the state folder: every 4 seconds while an effect is on (every 30 s otherwise) it records which layers are on and how much GPU `Hyprland` and the shell use (per process, from `nvidia-smi pmon`, so other apps do not count), their CPU use, VRAM, power and temperature. Nothing leaves the machine.

    omashaders perf report [--days N] [--notify]   cost per effect against the idle baseline, heavy ones first, plus crashes
    omashaders perf bench [--kinds screen,color,wall] [--only a,b]   try effects one by one (about 5 s each) and measure; your own effects are restored afterwards
    omashaders perf crashes [--hours N] [--all]    Hyprland / quickshell / portal crashes and what was on just before
    omashaders perf status | on | off              the sampler

Rating (extra GPU share of Hyprland + shell, median while on): light under 4, moderate under 12, heavy under 25, rework from 25 (or spikes of 40 and up). Measured moderate and heavy effects show `[heavy +18%]` after their description in the menu and in the active line. The log is rotated at 8 MB. Without an NVIDIA card the whole-GPU number from sysfs is used instead. The bench changes your live desktop for a minute or two and runs on a still screen, so it shows the cost of redrawing, not of busy content; a single reading can be off by 10 points, so trust the numbers that come with many samples (or run the bench twice) and let the sampler collect real use over a few days.

### Window frames: shadows, glows and borders (1.13)

The **Windows** column also has **Frame** categories (Shadow, Glow, Border, Spin) with 21 presets: soft, deep and offset shadows, neon / ember / aurora glows, thin gold, mono and chunky borders, and spinning rainbow borders. Hyprland draws shadows and borders itself (they are not shaders), so a frame is a preset of its own options (`decoration:shadow:*`, border colours and size, rounding) and **needs no plugin**. A frame applies to every window, not per app, and has no strength slider. Spin frames turn the active border with Hyprland's `borderangle` animation; the first turn starts after the next focus change (OmaShaders re-focuses the active window once for you). Off, or `window off`, puts back the look you had before, even after a config reload (`hyprctl reload` clears it, OmaShaders re-applies it). New presets are `.frame` files in the plugin's `frames/` folder (format in `docs/DEVELOPMENT.md`). Command line: `omashaders window frame list|status|set NAME|off`. Panels of other plugins that *All windows* does not know yet can be listed, one layer name per line, in the file `extra-layers` in the plugin's state folder (`omashaders window classes` shows the names it sees).

### Window shaders (optional, 1.11)

The **Windows** column (`W`) draws the same effects and colour grades as Screen and Color, but only on the app windows you pick, so the desktop, bar and other apps stay untouched. Pick who to edit in the **app box next to the Windows title** (click it, or press `A`): *All windows* (new windows are included as they open) or one app, then choose an effect and/or a colour from the categories (**Surprise me** there picks an effect for the app being edited); the box shows who you are editing. An app you edit gets **its own settings**, which are remembered per app and **override All windows** for that app (the first change starts from what All windows had, then only that part changes). Apps with their own setting show it in the app box. **Follow All windows** (in the app's column) removes the override, **Off** in an app's column gives that app no shader at all even when All windows has one, and **Off** under All windows clears everything. Frames stay global. Strength has one slider per part (Effect strength while you are in an effect category, Color strength in a colour one). Shell surfaces are listed in the same app box tagged `panel` (the bar, this OmaShaders menu, other plugins' menus and overlays): *All windows* includes them (plugin flyouts, menus, notifications, OSD), except the bar, the wallpaper, the cursor overlay and invisible click-catchers; tick the bar (or any panel) in the list to shade it too, and give a panel its own setting or **Off** to change just that one. Windows follow the pause key (`p`). Themes remember the Windows effect, colour and frame (all windows; per-app settings are not stored).

Hyprland cannot do this by itself, so it needs the third-party plugin [HyprWindowShade](https://github.com/ManofJELLO/HyprWindowShade) (MIT, compiled against your Hyprland version, so it cannot ship with this plugin). If it is missing, the Windows column shows what to install (**Copy install commands** puts it on the clipboard):

```
hyprpm update
hyprpm add https://github.com/ManofJELLO/HyprWindowShade
hyprpm enable HyprWindowShade
```

The plugin must be built for your Hyprland version; if `hyprpm add` fails, the plugin's newest commit may need a newer Hyprland than you run (pick an older commit). OmaShaders loads an installed but not yet loaded copy itself with `hyprctl plugin load` (it looks in `hyprpm`'s cache and in `~/.local/share/hyprland/plugins/HyprWindowShade.so`; with a `.md5` file next to a hand-built copy it checks the file first). It only sets shaders per app class and never adds window rules or tags. Command line: `omashaders window status|effect set NAME|color set NAME|strength effect|color N|target all|none|add CLASS|remove CLASS|toggle CLASS|here|apps|off`; for one app put `-a CLASS` first, e.g. `omashaders window -a kitty effect set vhs`, `window -a kitty strength effect 40`, `window -a kitty off|inherit|status`.

### Shift only (cursor effects)

While the menu is open the effects always show, so a cursor effect you pick appears at once; Shift only matters with the menu closed. Cursor effects can be limited to "only while Shift is held" (`x` in the menu); wallpaper effects always follow the pointer. For that, Hyprland has to tell the plugin when Shift is down; add this to `~/.config/hypr/bindings.lua` (the left and right Shift key each need both lines; the second one tells the plugin that Shift was let go, and without it Shift would count as held forever after the first press):

```lua
hl.bind("Shift_L", hl.dsp.global("omashaders:shift"), { non_consuming = true, dont_inhibit = true })
hl.bind("Shift_R", hl.dsp.global("omashaders:shift"), { non_consuming = true, dont_inhibit = true })
hl.bind("SHIFT + Shift_L", hl.dsp.global("omashaders:shiftup"), { release = true, non_consuming = true, dont_inhibit = true })
hl.bind("SHIFT + Shift_R", hl.dsp.global("omashaders:shiftup"), { release = true, non_consuming = true, dont_inhibit = true })
```

Shift still reaches your apps normally. Without these bindings the effects never show while the option is on (no press line) or stay on after one Shift press (no release lines).

### AI themes (1.27, full and subtle since 1.28, invent and AI tool picker since 1.30, chat since 1.31, Rich since 1.34)

The header of the menu has a button **Create your own theme (AI)** (key `T`, also in the Themes column). A panel opens: describe what you want in a few words ("a rainy neon night", "a warm cabin with snow outside, calm") and optionally tick **Use my current wallpaper as the base**. The AI answers with one theme, chosen **only from the effects that exist**: Screen, Color, Wallpaper, Cursor, and sometimes a Windows effect or frame, plus a few strengths and a name. OmaShaders checks every id against what is installed (unknown ones are dropped), applies the result live and shows progress and errors in the panel. **Nothing the AI returns is ever run or opened**: only effect ids and numbers are read, everything else is thrown away. In the Wallhaven browser, **Create theme from this** gives the picture to the AI as the base.

**It is a chat (1.31).** After the first answer the panel turns into a conversation: your messages on the right, the AI's on the left, and under every answer a **Changed:** list of what is different now ("Cursor removed (was Comet)", "Screen: Sunlit -> Dusk", "Wallpaper strength: 85% -> 50%"). Type a follow-up and press Enter: "make the windows red like the car", "less fog", "swap the cursor for something calmer". The AI gets the current theme and the conversation so far and answers with **only what changes**; everything you did not mention stays, and a follow-up never raises strengths on its own. The new look is applied live every time. Nothing is added to your themes list until you decide:

- **Save as theme** (button, `s`, or Enter on an empty line) saves it as a normal theme with the AI's name (a theme with exactly the same parts is not added twice) and keeps the effects the AI invented that the theme uses. 
- **Discard** (`d`) throws the chat away, brings back the look you had before and deletes what the chat invented; the panel stays open for a fresh start. **Esc** does the same and closes the panel (Esc while the AI is working only cancels that turn).
- **Settings** (`o`) shows the AI tool and model again during a chat. Switching to another menu (a popout) saves the theme instead of throwing it away.

A chat is limited to 40 turns. The base picture is sent only with your first message; follow-ups send the picture's measured colours and the current theme as text. From a terminal: `ai-theme chat turn "less fog"`, `ai-theme chat keep`, `ai-theme chat discard`, `ai-theme chat status` (see `docs/DEVELOPMENT.md`).

**Full or Subtle.** The default is a **full theme**: the AI states the idea first (the story it read in your picture), then fills all six parts that fit, with the wallpaper overlay at 70-100 % (default 85), cursor 70-100 %, screen and colour at least 60-65 %, so the result is clearly visible. Text stays readable and heavy stacks are avoided. Tick **Subtle** (key `S`, or `--subtle`) for the old quiet behaviour: a colour grade, a gentle screen effect, an overlay at 30-60 %. The overlay is picked from the story: speed and cars get `speedlines`, `lightstreaks` or `roadglints`; sun gets `lensflare`, `sunburst` or `heatshimmer`; sky `cloudsdrift` or `skybirds`; night city `bokehlights`, `neonglints` or `citytwinkle`; water `watersparkle`.

**Pick existing or Invent new (1.30).** The dialog has two modes. **Pick existing effects** is the mode above (the AI chooses from what is installed; cheap, works with any model). **Invent new effects** lets the AI write NEW shaders for Screen, Color, the Wallpaper overlay, Cursor and the Window shader, and a Frame, so the theme is not limited to the catalog: it gets the picture's exact palette (hex colours measured from the picture) so shaders hard-code the right reds and blues, and it may still reuse an installed effect where one already fits. Under the prompt are six optional boxes, one per part ("Window shader: in the car's red", "Cursor: a small comet tail"). The prompt for this mode is small (about 1.7k tokens of instructions: the template, the interfaces and five short examples, in the *Inventing new effects* chapter of `docs/theme-instructions.md`, plus only the *names* of installed effects), not the big catalog. Before you start, the dialog shows an estimate (tokens in and out, dollars for Claude), and afterwards what was really used. Inventing needs a strong model: with a small local model the panel recommends *Pick existing*, and that is the default for Ollama.

**Quick or Rich (1.34).** The dialog has three buttons in its mode row: **Pick existing**, **Invent: Quick** (the one-call Invent above, cheap, the right choice for small or local models) and **Invent: Rich** (key `m` cycles them). Rich works like a small studio instead of one call that writes everything:

1. **Planner.** One call first thinks about the *theme*, not the code: the place or biome, the time of day, the mood, a two-sentence story, a palette with roles (sky, accent, shadow ...), how it moves, how it reacts to the pointer, one playful detail, and why you would keep it on all day. It sees your picture, its measured colours and tags, a few of the shipped themes as examples of the standard, and the titles of your own themes (it does not repeat them). It ends with one short brief per part: Screen, Color, Wallpaper overlay, Cursor, Windows, Frame.
2. **Builders.** One call per part, in parallel where the AI tool allows it (Claude, Codex, Gemini). Each gets the whole concept, its own brief, the interface for its target, a shared library of GLSL helpers (soft noise, caustics, rays, sparks, streaks, mist ...) and two shipped effects of the same kind that match the style. Rich pieces may be larger than Quick ones (up to 18 000 characters instead of 9 000, more loop work per pixel; numbers in `docs/DEVELOPMENT.md`) but go through exactly the same safety gate. A wallpaper overlay must have at least two layers at different speeds, motion and a reaction to the pointer, and still may not repaint your picture.
3. **Reviewer.** Each piece that passes the gate is rendered offscreen over *your* picture (at a first and a second moment, and once with the pointer moved) and a vision call looks at the contact sheet next to the brief: a score from 1 to 10 and concrete fixes. Pieces under 7 are rewritten with those fixes, up to **Review rounds** times (the button in the dialog, 0 to 3, default 2; 0 skips the Reviewer). A rewrite that scores lower is dropped. A piece still under 4 is replaced by the closest shipped effect, and the result card says so.

**Surprise me.** With Rich, leave the box empty (or press **Surprise me**, key `u`): the Planner invents the theme from the picture alone, or from nothing when there is no picture. The optional **Genre** box ("cozy cyberpunk", "deep sea") nudges it. **The result card** under the chat shows the Planner's concept (title, place, time, story, palette chips, the six one-line briefs with their Reviewer scores) and a contact sheet of the renders (`r` hides or shows it), then **Save as theme**, **Discard**, or keep talking. A follow-up such as "make the cursor calmer" changes **one part**: only that part's Builder runs again; nothing else is rebuilt. Before you press the button the dialog shows an estimate ("Rich: about 167k tokens, about $0.97, 17 calls" with Claude Sonnet at API prices, next to about $0.05 for Quick) and after the run the real tokens and dollars of every step. Rich needs an AI tool that can look at pictures for the Reviewer (Claude, Codex and OpenCode can); without one the Reviewer is skipped and the card says so. Terminal: `ai-theme make "words" --rich [--rounds N] [--genre TEXT] [--surprise] [--keep-out DIR]`, `ai-theme estimate --rich`.

**What happens to a generated shader (the safety gate).** The AI never writes a whole shader file. It writes only a function body that is dropped into a fixed template. Before anything is used (`bin/aigen.py`):

1. *Text rules:* ASCII only, at most 9000 characters / 320 lines, no `#include`, `#define`, `#extension` or any `#` line, no `uniform`, `layout`, inputs, samplers, `discard`, constant arrays or recursion, only known GLSL functions, a `for` loop must be written `for (int i = 0; i < N; i++) { ... }` with a constant bound of at most 64 and a body in braces, at most 48 `texture()` samples and 500 loop iterations per pixel (nested loops and called functions counted), and a work limit per pixel. A colour grade may only change colours, a cursor effect may not read the picture. These are the Quick numbers; Rich pieces get larger ones (18 000 characters, 520 lines, 64 samples, 800 iterations, more work per pixel) and every other rule is identical.
2. *Compile:* the final shader must compile (Hyprland screen shaders with `shader-check`, wallpaper and cursor shaders with `qsb`).
3. *Test render:* the shader is rendered offscreen at 1920x1080 on the CPU against a sample desktop within a 25 s budget. Flat, all-black or all-white results are refused; text on two sample panels must stay readable at the start strength; a wallpaper overlay must change the picture (at least 0.8 %) but never repaint it (mean change at most 20 %, strong at most 40 %); a cursor effect must stay local and must draw something.
4. *Repair:* a part that fails goes back to the AI with the exact reasons, at most 2 times. If it still fails, the closest installed effect is used and the dialog says so. The rest of the theme is not affected.

Generated files live only in your state folder (`~/.local/state/omarchy/io.github.akton1.omashaders/generated/`), never in the plugin folder, so an update never touches them and they are not part of the plugin you installed. They work like any other effect: strength slider, mixing, themes, and they load without restarting the shell. Each has a name and description (shown in the menu), the group **Made by AI**, and a `meta` record with your prompt. Effects the chat invented stay pending until you **Save as theme** (the ones the theme uses are then kept, the rest deleted) or **Discard** (all deleted). Delete one later with `Delete` in the menu (press twice) or `omashaders ai discard ID`.

**Share codes and generated effects.** A share code carries only effect names, never shader code, so a code that uses an effect made by AI cannot be shared: `share` refuses it with a message (save a theme from installed effects to share it); on import, an `ai-` name in a code is left out. Importing never loads code from a code either. This was a deliberate choice: running shader text that arrived from a stranger is exactly what the safety gate exists to avoid.

**Choosing the AI.** The dropdown **AI tool** in the dialog (and the *AI tool*, *AI model* and *Custom AI command* settings in the plugin settings) lists only the tools found on your computer: `claude`, `codex`, `gemini`, `opencode`, `ollama`, plus **OpenAI-compatible endpoint…** and **Custom command…**. Until you pick, it preselects the agent set with `omarchy default agent` (if it is one of these and installed), otherwise the first installed tool. Each has a tested non-interactive call, always without a shell, with the prompt on stdin (or as an attached file for OpenCode): Claude Code uses `claude -p [--model MODEL] --tools "" --strict-mcp-config --setting-sources "" --no-session-persistence`; Codex `codex exec --ephemeral -s read-only` in an empty temporary folder; Gemini `gemini -p … --approval-mode plan`; OpenCode `opencode run -f prompt.txt`; Ollama `ollama run MODEL`. A **Model** box takes any model id (empty means the tool's own default, nothing is passed); a dropdown offers shortcuts where there are some (Claude: Sonnet, Opus; Ollama: the models you pulled). **Test connection** sends one tiny request and tells you if it works. Your choice is remembered (`ai.json` in the state folder); the plugin setting seeds it and changing the setting changes it. The old `aiCommand` setting still works and becomes the Custom command: any command that reads the prompt on stdin and prints text containing one JSON object; a word `{image}` is replaced by the path of the small JPEG when there is a picture. If the chosen tool does not exist, every AI button says **AI needed** and shows what to do.

**OpenAI-compatible endpoint.** For a model that no installed tool runs, type the server address (for example `https://openrouter.ai/api/v1`, `http://localhost:1234/v1` for LM Studio, `http://localhost:8080/v1` for llama.cpp, `http://localhost:11434/v1` for Ollama), the model name, and, if the server wants one, where the key lives: the name of an environment variable the shell can see, or the path of a private file (`chmod 600`; a file others can read is refused). The key is read when a request is sent and is never written to the plugin's files, the logs or an error message. The request is a plain `POST …/chat/completions` with the system text, the prompt and, if you ticked that the model can look at pictures, the small JPEG. A server on the internet must be `https://`; `http://` is accepted for this computer and your home network only. Redirects are not followed. The two tick-boxes **This AI can look at pictures** and **Strong enough to invent effects** apply to endpoints and Custom commands; without a picture-capable AI, Rich skips the Reviewer.

**Privacy: what is sent where.** Nothing is sent until you press the button. Then the prompt (your wish, your part orders, the names of installed effects, the picture's measured colours, for Wallhaven pictures its tags, and the instructions) goes to the one tool you chose, which sends it to that tool's own service under its own terms: Claude Code to Anthropic, Codex to OpenAI, Gemini CLI to Google, OpenCode to whichever provider you configured in it, Ollama stays on your computer, an OpenAI-compatible endpoint receives it at the address you typed, a custom command goes wherever you point it. With Claude, Codex and OpenCode the prompt also includes a small JPEG copy (at most 768 px) of the base picture; Gemini and Ollama get only the colours and tags as text. The full-size picture never leaves your computer. Shader code that comes back is checked and rendered locally; it is never sent anywhere.

**Painted sprites (optional, off by default).** Tick **Painted sprites (uses your image model)** in the theme dialog (Quick and Rich) and the new wallpaper effect also gets eight small pictures, for example a glowing paper lantern, that its shader draws and moves. The image model is yours and nothing is named for you: **ComfyUI** (address, default `http://127.0.0.1:8188`; the checkpoint list is read from your ComfyUI; an optional workflow file in API format with `{prompt}`, `{negative}`, `{width}`, `{height}`, `{seed}` and `{checkpoint}` placeholders), an **OpenAI-compatible images endpoint** (`POST …/images/generations`, the key read from an environment variable or a private file, same rules as the chat endpoint above), or a **Custom command** (run without a shell; `{prompt}`, `{out}`, `{width}`, `{height}` and `{seed}` are filled in and it must write a picture to `{out}`). **Test connection** is free: it asks the server what it has and paints nothing. Only the eight short sprite descriptions go to the image model, one picture each; your wallpaper and the words you typed are not sent. What comes back is accepted only if it is a real picture (checked by its file signature and size), the plain background is cut away locally and the eight cells are packed into one PNG next to the effect. Pictures are data, never run, and never part of a share code. If the image model is down or answers with junk, the theme is made without sprites and the dialog says so. A painted result is less predictable than the art that ships with the plugin. Your wallpaper itself is never created or replaced.

**What a call costs:** *Pick existing* is about 21-23 thousand input tokens and a few hundred output tokens per request (the list of all effects makes up most of it), about 8-9 US cents with Claude Sonnet at API prices, or a small slice of your Claude subscription limit. *Invent new* sends fewer input tokens (about 6-8 thousand with a picture) but writes more (about 450 tokens per new part, each repair try adds roughly that again). The panel shows an estimate before you press the button and the real count after. Check from a terminal with `omashaders ai check`, make a theme in one go with `omashaders ai make "a rainy neon night" [--wallhaven ID | --current]`.

**Your picture stays the wallpaper.** A theme never creates or replaces a picture. **Create theme from this** (Wallhaven) first sets the chosen picture as your wallpaper, the same way **Use as wallpaper** does, and only then builds the theme so the ambient fits it; with **Use my current wallpaper as the base** the picture is already set. The AI only picks existing effects: Screen, Color, Cursor, Windows part and frame, plus at most one *light overlay* for the Wallpaper part (snow, rain, fog, petals, rays, dust motes, embers and similar, 19 of the ~170 wallpaper effects; they are listed in `wallpaper-effects/overlay.tsv`, measured by `bin/wallpaper-overlay-scan`). Scenes that repaint the picture are never offered, are dropped if the AI names one, and an overlay is limited to 70 % strength (55 % when the AI gives none). The starter themes still use the full scenes; this rule is only for AI themes.

The instructions the AI gets are in `docs/theme-instructions.md` (versioned like the plugin). Edit that file to change the taste of the results.

### Share and import (1.27)

Press `S` (or click **Share** in the Themes list) to open the Share window for the selected theme, or for the look that is on now when no saved theme is selected. All parts are in the code by default; switch Screen, Color, Wallpaper, Cursor or Windows off (keys `1`-`5`) to leave one out, then press `Enter` (**Create code**) to get a code like `OMS1:eNpL…`. It is copied with `wl-copy` and shown in the window. Command line: `bin/theme-code share N --parts screen,color`. The code holds the theme name, the effect ids, the strengths, wallpaper speed and zoom, the custom colour and, when the base picture came from Wallhaven, its id. It never holds file paths, your name or any image data.

Press `i` (or **Import theme**) to paste a code (the clipboard is read for you). The code is read strictly, as data only, and a **safety check** runs first (the dialog and the command say so): it must hold nothing but known fields, effect ids or hex colours, numbers and a plain Wallhaven id; a path, command-like text, shader code, an unknown field or a malformed value makes the import refuse and nothing is saved. Then it is size limited, every id is compared with what this version has, and anything unknown is reported ("this theme needs the wallpaper effect X, which this version does not have; a newer OmaShaders may") and left out. The rest is saved as a normal theme (always your own, deletable, even if it equals a built-in one) and optionally applied. If the code names a Wallhaven picture, the dialog shows its link text (`wallhaven.cc/w/<id>`, no thumbnail is fetched), says whether the picture is already on this computer, and sets it together with the theme: the main button reads **Download wallpaper and apply theme** when the picture still has to be downloaded (only the id from the code is used, only from wallhaven.cc, and only after you press the button), and **Apply theme only** keeps your wallpaper. A failed download never loses the theme; the dialog offers **Retry**. The share dialog states whether the code **includes a Wallhaven wallpaper** or, for a wallpaper that is a local file or an AI picture, that the code carries the theme only. From a terminal: `omashaders theme share N` (N is the position in the Themes column) and `omashaders theme import CODE [--apply] [--wallpaper]` (`--wallpaper` downloads and sets the code's Wallhaven picture; without it only the theme is saved and the command says a picture is available).

Themes saved from now on also remember the strengths of the effects that are on, the wallpaper speed and zoom, and the Wallhaven id of the wallpaper when it came from Wallhaven (an optional ninth field in the theme file). Older themes have no such numbers and, when applied, leave your strengths alone.

### Share a theme as a picture (1.37)

The Share window (`S`) has two buttons: **Create code** (the text code above) and **Record sharable GIF** (`g`). The second records your current look (the parts you left switched on) as a short GIF, 960 px wide, under 5 MB, with the theme code drawn as dark and light squares (Reed-Solomon protected) in the top and bottom border of every frame, and a short line of text in the bottom border: "Right-click > Copy image, open OmaShaders > Import theme". The GIF is saved in `~/Pictures/OmaShaders/` and copied to the clipboard, so you can paste it into a post. Because every frame carries the code, any frame works, and the squares survive GIF palettes, scaling and lossy video re-encoding (tested down to half width). The border grows with the code: a typical single custom shader is about 1 KB and adds a border of about 180 px; the picture holds up to about 5.4 KB, above that the button says the theme is too big for a picture and the text code is the way.

**Import theme** (`i`) accepts a text code, a copied picture (clipboard), a saved GIF/video/image file or a screenshot of the post. It reads the squares, runs the same strict checks as a text code, applies the theme as a preview and asks **Keep** or **Undo**; Undo removes the theme and any shaders that import added.

**Custom shaders (`OMS2:` codes).** Themes that use only shipped effects are shared as the short `OMS1:` code (effect ids only). A theme that uses effects you made with the AI (**Made by AI**) is shared as an `OMS2:` code that also carries those shaders: comments and whitespace are stripped and the text is compressed with a built-in dictionary of GLSL words and the plugin's helper functions. On import every shader goes through the AI safety gate (fixed template, no includes, bounded loops, compile, test render, text still readable); a shader that fails is left out and listed, and the rest of the theme still imports. Imported shaders appear under **Made by AI** and can be deleted any time. Codes carry a format version and a dictionary id, so a code from a newer version is refused with "made by a newer OmaShaders" instead of misbehaving. Command line: `omashaders` runs `bin/theme-code share|import|check|undo|keep` (see the header of the file); `bin/omsborder.py decode IMAGE` prints what a picture holds.

Needs `python-pillow` and `python-numpy` for the picture border (without them only the text code works) and `ffmpeg` to read a video. **A picture only holds what the text code holds plus your own custom shaders: no file paths, no user name, no images.**

### Deleting effects and themes, built-in protection (1.33)

`Delete` deletes what the cursor is on, or pick **Delete selected** in the list of actions of a part (it acts on the item you pointed at last; the Themes list has no such row, use `Delete`). Effects ask first: "Used by theme: Abyss, Moon Lake. Delete anyway?" names the themes that use it; press `Delete` again within a few seconds to confirm (a plain "Delete NAME?" when no theme uses it). A theme that loses an effect keeps its other parts and simply applies with that part empty; an effect that is on at that moment is switched off first. Themes are removed with `f` or `Delete`.

**Built in** means shipped with the plugin: the starter themes (listed in the `starter-themes` file) and the effect files in the plugin folder. Users cannot delete them: the menu shows "Built-in theme, cannot be deleted" (or "Built-in effect, cannot be deleted") and nothing happens. Your own themes (saved, imported or made in the AI chat) and your own effects (**Made by AI**) can always be deleted. If you rename a built-in theme (`n`) the rename is saved as your own copy and the built-in original stays. The built-in mark is only the shipped list: a theme counts as built in when its whole line is in `starter-themes` (its short id, shown by `theme list`, is a hash of that line), so there is no author, user id or other personal data anywhere, and a share code never carries it. The developer's switch (the empty file `dev-export` in the state folder, see Configuration) lets the author delete built-ins on their own machine, and the shipped list follows.

From a terminal: `omashaders theme list` (numbers, short ids, `[built-in]`), `omashaders theme rm N --yes`, `omashaders element rm KIND NAME --yes` with KIND one of `screen`, `window`, `color`, `wallpaper`, `cursor`, `frame`. Without `--yes` they only print the same question the menu asks and exit with 2; a built-in is refused with the same note (exit 1).

### Record a GIF (1.29)

For a preview picture of a look (a store page, sharing with a code). Open the Share window (`S`) and press **Record sharable GIF** (`g`; see *Share a theme as a picture* above), or run `omashaders gif [--seconds N] [--out FILE]` for the same recording without a code border (also `omarchy-shell io.github.akton1.omashaders gif`). What happens:

1. The menu closes. The pointer's monitor switches to an empty workspace, so your windows are hidden (they are not touched), and the bar is hidden. Notifications are held back for the few seconds it takes. A **demo terminal** is prepared out of sight on that workspace and shown during the recording, so every picture shows the same terminal and nothing of yours: a rounded window in the look of the Abyss preview GIFs, with your wallpaper around it, that types `omashaders theme apply` with the name of your theme and lists its screen, colour, wallpaper and cursor parts (your look, not made-up ones), then a second small command. Its colours, font and size are fixed and scale with the monitor; a window effect limited to some apps is extended to it for the recording only.
2. A small centred number counts 3, 2, 1. **Esc** cancels; everything is put back.
3. The monitor is recorded while the pointer draws an S along the bottom (about 4 seconds, `--seconds`, 1 to 5; eased, so it starts and ends slowly) and then climbs up the right side to the top right, never through the centre. The picture starts with the bare wallpaper and your cursor effect. When the pointer is a third of the way in from the left, the demo terminal opens and starts typing, and the pointer climbs through its right part, so a window effect (a glow under the pointer, for example) shows too. The recording ends a moment after the typing is done.
4. Windows, focus, bar and pointer position are restored **before** the encoding starts. The GIF is made with ffmpeg (palette, 960 px wide, 15 fps, loops forever) and made smaller step by step (down to 480 px, 10 fps) until it is under 5 MB. It is saved as `~/Pictures/OmaShaders/<theme name>-<date>.gif`, the GIF is copied to the clipboard with `wl-copy` (as an image, so you can paste it straight into a post), and a notification shows it.

If effects are paused the GIF shows none, and the notification says so. If anything fails, or the script is killed, a saved state file puts the desktop back (`omashaders gif restore`, also run every time the shell starts). **Nothing else is allowed in the picture:** before the recording starts and all through it, any other window or layer-shell surface on the monitor (a notification, another program's overlay) stops the recording with a message that names it, and no GIF is made; close it and record again. A running F9 screen recording blocks it (stop that one first).

### Follow effects

Cursor > Bend > Follow: eight gentle effects that bend or re-draw the real screen along the pointer's recent path and settle after you stop: `smudge` (pixels smear forward like dragged wet paint), `melt` (a soft drip behind the pointer), `wake` (a narrow boat-wake ribbon), `drift` (a faint lens that lags behind and catches up), `streak` (motion blur near the pointer) `echo` (a faint afterimage) and `decode` (screen cells near the moving pointer scramble into green Matrix-style glyphs and decode back to the real pixels as you move on) and `smoke` (a visible wisp of smoke, light on dark screens and dark on bright ones, that is pulled along behind the pointer, curls and thins out upward after you stop). They are small (45-150 px) and fade out within half a second, so text stays readable. `bin/cursor-bend` passes the last 8 pointer positions (35 ms apart) to the shader as `CTR`.

## Configuration

Plugin settings (Omarchy settings UI):

| Setting | Default | Meaning |
| --- | --- | --- |
| `fps` | 30 | frame rate of wallpaper and cursor effects |
| `cursorNeedsShift` | off | start value of "cursor effects only while Shift is held" |
| `aiProvider` | Remembered choice | the AI tool behind "Create your own theme (AI)": Claude Code, Codex, Gemini CLI, OpenCode, Ollama, OpenAI-compatible endpoint or Custom command (with "Remembered choice" and no pick yet, the agent from `omarchy default agent`). The theme dialog has the same dropdown and remembers its last pick (see AI themes) |
| `aiModel` | empty | model for that tool (empty = its own default; any model id it or the endpoint accepts, e.g. `opus`) |
| `aiCommand` | empty | the Custom command: reads a prompt on stdin, prints text with one JSON object (see AI themes) |

**Starter themes:** the Themes menu comes with ready-made combinations (file `starter-themes`, kept in step with the author's own list). Each release adds the new ones to your list, once: a theme you removed with `f` does not come back, and your own themes are never changed. To ship your own set from a checkout, create an empty file `dev-export` in the state folder; then every save or remove also rewrites `starter-themes`, and built-in themes and effects can be deleted (without the file nobody can delete them).

State lives in `~/.local/state/omarchy/io.github.akton1.omashaders/` (current effects, mixes, strengths, favourites, themes, pause flag, built shader files). Hyprland forgets a runtime screen shader on a config reload; the icon re-applies it.

## Permissions and behaviour

- **Network:** nothing is downloaded or sent unless you use one of these features. (1) The **Wallhaven browser** (`bin/wallhaven`, curl) talks to wallhaven.cc and its image servers when you open the browser, search, or choose a picture; it sends your search words and filters and nothing else (no key, no account, no identifier). (2) **AI themes** run the AI tool you chose (by default the agent set with `omarchy default agent`), or call the endpoint you typed. Either way your wish, the list of effect names and, if you asked for it, a small copy of the base picture and its colours go to that tool's AI service (or to the endpoint), under its own terms (details under AI themes > Privacy). (3) **Painted sprites**, if you tick them, send eight short sprite descriptions to the image model you chose: ComfyUI at the address you typed, an images endpoint, or a command of yours. (4) The **What's new** icon runs `git fetch` on this plugin's own repository (`bin/update-check`, read-only) when you open the menu, at most every 30 minutes, and **Update now** runs `omarchy plugin update`. Share codes and importing never touch the network, except that importing a code with a Wallhaven picture downloads that one picture from wallhaven.cc when you press **Download wallpaper and apply theme** (or pass `--wallpaper`). Without those features the plugin stays offline.
- **Clipboard:** the plugin never reads your clipboard on its own. Its text boxes are drawn by `PlainField.qml` (no Qt text-input item), so a clipboard change in another program is not read by the shell. Only when you press `Ctrl+V` or `Shift+Insert` in a box, or use Import theme, `wl-paste` runs as a separate process (2-second deadline, size limited to what the box accepts) and its first lines are inserted.
- **Hyprland:** the screen effect is set at runtime with `hyprctl eval` (`decoration:screen_shader` and `debug:damage_tracking`). Nothing is written to your Hyprland config files; a `hyprctl reload` or `off` clears it.
- **Subprocesses:** `bin/omashaders` (sets the shader), `bin/compose-shader` (python, merges effect and colour into one file), `bin/cursor-watch` (python; reads the pointer position from the Hyprland socket about 40 times a second, only while a pointer-following effect is running, and exits with the shell), `bin/gpu-usage` (`nvidia-smi` or sysfs, only while the menu is open), `bin/perf-log` (python; the cost log described above, started with the shell, one copy only; `omashaders perf off` stops it; it runs `nvidia-smi` and `pgrep` every few seconds, and `coredumpctl` only when you ask for a report), `bin/wallpaper-step`, `bin/wallhaven` (python and curl, only for the Wallhaven browser), `bin/ai-theme`, `bin/aiprov.py`, `bin/aiinvent.py`, `bin/airich.py`, `bin/aisheet.py`, `bin/aigen.py` (run your chosen AI tool, check and render what it writes, only for AI themes), `bin/aisprites.py` and `bin/imgprov.py` (only for Painted sprites: call your image model, cut the pictures out), `bin/update-check` (the What's new icon), `bin/gif-capture` and `bin/gif-clip` (Record GIF; `gif-clip` is a small GTK helper that stays alive to serve the GIF on the clipboard until something else is copied), `bin/theme-code` (share and import codes; `wl-copy` and `wl-paste` for the clipboard), and `notify-send` for the pause key.
- **Wallpaper picker and next/previous:** these change your wallpaper with Omarchy's `omarchy-theme-bg-set`, on your click only. Picking makes a temporary folder of symlinks to your background images under `$XDG_RUNTIME_DIR` and removes it afterwards.
- **Files written:** only the state directory above (including the Wallhaven cache under `wallhaven/`) and the temporary folder just mentioned (and a short-lived temporary JPEG when a picture is sent to an AI), plus the GIFs and share pictures you record yourself in `~/Pictures/OmaShaders/`, and the private job and sprite files of an AI theme while it is being made, inside the state directory. Existing config of yours is never overwritten.
- **Bend cursor effects:** a screen shader cannot see the pointer, so while one is selected `bin/cursor-bend` (python; polls the pointer from the Hyprland socket 60 times a second, writes a new shader file at most 30 times a second and only while the pointer moves, plus a short tail for the ripple-like ones) hands Hyprland a fresh composed shader through `hyprctl eval`. Screen and Color effects stay active, merged into the same shader. It starts and stops with the effect, exits with the shell, and then puts your normal shader back. With several monitors a 3x2 pixel marker (magenta, green, magenta) is drawn in the top-left corner of the pointer's monitor so only that monitor is bent; the shader hides it again.
- **Window shaders:** the optional HyprWindowShade plugin is loaded into Hyprland with `hyprctl plugin load` (only when you set a window effect, or at login if one is set) and told per app class which shader file to use through `hyprctl eval`. Nothing is installed, built or downloaded by this plugin.
- **Windows:** wallpaper and cursor effects are drawn in click-through layer-shell windows, one per monitor, that do not take keyboard focus. The menu takes keyboard focus while it is open.
- **Bundled binaries:** the `.frag.qsb` files are compiled Qt shader packages (data, not programs), built from the `.frag` sources next to them with `bin/build-*-effects`.

## Update

The newspaper icon in the menu header lists what's new (the "What's new" section of this README). When a newer version is published it turns coloured and gets a NEW tag (checked when you open the menu, at most every 30 minutes, with a `git fetch` of this plugin's repository). Click it (or press `Shift+U`) for what changed and an **Update now** button, which runs the command below; then restart the shell to load the new version.

```
omarchy plugin update io.github.akton1.omashaders
```

## Troubleshooting

- **Red Hyprland warning about `time` and damage tracking:** an animated effect was applied by something other than this plugin. Pick a static effect or `off`, then run `hyprctl reload`.
- **An effect makes text unreadable:** lower its strength (`[`), or press `d` for its start value. Pixel effects start low on purpose.
- **Icon missing or the menu looks old after an update:** `omarchy-restart-shell`. Updating from a version before 1.21 needs that one restart to load the new bar widget; after it, edits to the plugin's own QML files reload by themselves (developers: see `docs/DEVELOPMENT.md`).
- **Bend effects cost more than overlays:** the pointer position reaches the shader as a new file about 30 times a second, so Hyprland recompiles it each time (roughly 35% of a CPU core on the author's machine while the pointer moves, none while it rests). Use an overlay effect if that matters.
- **Bend effect only shows on one monitor:** intended, it follows the pointer.
- **Cursor effects never show:** you turned on "only while Shift is held" without the Shift binding above.
- **Windows column says "Setup needed":** HyprWindowShade is not installed (see Window shaders above). After installing, reopen the menu.
- **A window shader does not appear on one app:** the target is the app class (shown in the Apps list while the app is open); a window opened before you picked the effect is covered as soon as its class is targeted. Chrome / Electron apps with several windows share one class.
- **GPU line empty:** neither `nvidia-smi` nor an AMD sysfs reading is available.

Report bugs at https://github.com/AktOn1/omashaders/issues. How the effects work and how to add your own: [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).
